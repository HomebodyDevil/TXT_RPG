# 주사위 효과 면과 Story 결과 기록

## 목적과 확정 사항

숫자만 보유하던 주사위 면을 효과 종류와 수치를 가진 데이터로 전환한다. 현재는 공격과 회복 두 종류를 제공하며 추후 효과 추가 및 3D 결과 판정과 연결할 수 있게 한다.

사용자가 확인한 범위는 다음과 같다.

- 이번에는 효과·수치 데이터, 런타임 면 변경, 굴림 결과와 StoryTextPanel 기록까지 구현한다.
- 실제 피해·회복, 대상 선택, 체력 변경, 턴 진행은 구현하지 않는다.
- 임시 D4/D6/D8은 공격·회복을 번갈아 배치하고 기존 면 숫자를 수치로 유지한다.
- 기존 임시 플레이어 세션 소유·재실행 초기화 정책을 유지한다. 저장·장착은 추가하지 않는다.

이 문서는 예정된 구현 지침이다. 아래 제안 타입과 3D 연결 계약을 이미 구현된 기능처럼 기술하지 않는다.

## 효과 면 모델

최소한의 불변 값 타입(예: DiceFace)을 두고 EffectKind와 Amount를 보유한다. 공격·회복은 표시 문자열이 아닌 안정적인 내부 식별자로 표현한다. enum을 사용한다면 명시적인 값을 부여하고 추후 순서를 바꾸거나 값을 재사용하지 않는다. Unknown/기본값을 정상 공격으로 조용히 취급하지 않는다.

면마다 이번에는 효과 하나와 정수 수치 하나만 가진다. 복합 효과 목록, 수식 엔진, 범용 상태 이상 프레임워크는 추가하지 않는다. 효과 표시명은 표현 계층에 두며 도메인이 한국어 문자열·UI·Unity 물리 API를 참조하지 않게 한다.

면 수는 면 목록 길이로 결정한다. 동일 효과·동일 수치가 여러 면에 있어도 중복을 제거하지 않는다. 현재 난수 방식은 모든 면을 같은 확률로 선택한다.

기존 개발자 지정 정수 허용 범위는 Amount 검증에 유지한다. 기본 임시 구성은 1~면 수다. 기존 숫자 범위 정책을 임의 변경하거나 음수를 반대 효과로 해석하지 않는다. 실제 효과 실행 시 필요한 수치 의미·대상·방어력 처리는 추후 확정한다.

전체 목록·개별 면·허용 범위 변경은 먼저 검증하고 원자적으로 반영한다. 실패 시 기존 상태를 보존한다. 입력 배열을 복사하고 외부에서 검증을 우회해 수정하지 못하게 한다. 이전 굴림 결과가 나중의 면 변경에 따라 바뀌지 않아야 한다.

## 임시 면 구성

첫 면은 공격으로 시작하고 이후 회복과 교대로 배치한다. 다음 값은 임시 초기 구성이며 운영 밸런스 확정이 아니다.

| 주사위 | 순서대로 배치할 면 |
| --- | --- |
| D4 | 공격 1, 회복 2, 공격 3, 회복 4 |
| D6 | 공격 1, 회복 2, 공격 3, 회복 4, 공격 5, 회복 6 |
| D8 | 공격 1, 회복 2, 공격 3, 회복 4, 공격 5, 회복 6, 공격 7, 회복 8 |

Inspector에서는 면별 효과와 수치를 편집할 수 있게 한다. 설정 원본과 세션 인스턴스 상태를 분리하고 Play 중 변경이 원본 ScriptableObject에 저장되지 않도록 한다.

## 굴림과 3D 연결 경계

현재 난수 선택과 미래 물리 선택을 분리한다. 난수 Roll은 면 인덱스를 선택한 뒤 공통 결과 생성 경로를 사용한다. 미래 3D 어댑터는 판정한 면 인덱스 또는 안정적인 Face ID를 같은 결과 생성 경로에 전달할 수 있어야 한다. 외부에서 선택한 면으로 결과를 만드는 경로는 난수를 다시 호출하지 않는다.

결과에는 면 식별 정보, 효과 종류와 당시 수치를 보존한다. 주사위 인스턴스 식별자는 기존 PlayerDieRoll 경계를 활용한다. 선택과 효과 실행을 같은 메서드의 숨은 부작용으로 묶지 않는다.

이번에는 3D 모델·Collider·Rigidbody·면 판정 컴포넌트를 구현하지 않는다. 향후 구현 시 필요한 다음 계약을 문서에 남긴다.

- 각 모델의 물리 면과 논리 면을 명시적으로 매핑한다. 메시 삼각형 순서·자식 이름에 우연히 의존하지 않는다.
- 사용자 표현인 ‘바닥과 수직인 윗면’은 일반적인 상단 면의 경우 면 자체가 아니라 면의 바깥쪽 법선이 바닥 기준 위쪽에 가장 가까운 상태로 해석해야 한다. 기준 바닥·중력·허용 각도는 실제 물리 구현 때 확정한다.
- 주사위가 움직이는 동안에는 결과를 확정하지 않는다. 정지 판정, 기울어진 상태, 여러 후보 면, 장외·타임아웃 등의 처리 규칙은 추후 결정한다. 애매한 결과를 임의로 재추첨하지 않는다.
- 일반 사면체 D4는 바닥에 놓이면 위쪽 꼭짓점이 나타나므로 D6/D8의 상단 면 판정을 그대로 적용할 수 없다. D4 전용 매핑·판정 규칙은 추후 사용자 확인 대상으로 남긴다.
- 난수 방식의 면별 동일 확률이 물리 주사위에서도 자동 보장된다고 주장하지 않는다. 모양·질량·마찰에 따른 검증이 별도로 필요하다.
- 굴림 시작부터 결과 확정까지 면 구성 변경을 금지하거나 버전·스냅샷으로 일관성을 보존하는 계약이 필요하다. 미래 비동기 경계를 고려하되 이번에는 실제 물리 상태 머신까지 만들지 않는다.
- 미래 효과 실행은 확정된 굴림당 한 번이어야 한다. 충돌·정지 이벤트가 여러 번 발생해 중복 발동하는 문제를 실행 계층에서 방지하도록 한다.

## StoryTextPanel 기록

기존 GameMenuPanel 명령, 보유 순서, 주사위당 한 메시지 추가를 유지한다. 결과 예시는 다음과 같다.

```text
[주사위] 1번 주사위 (D4): 공격 3
[주사위] 2번 주사위 (D6): 회복 4
[주사위] 3번 주사위 (D8): 공격 7
```

문구는 결과 데이터에서 생성하며 면 인덱스를 수치로 출력하지 않는다. ‘HP 4 회복 완료’, ‘피해 7 적용’처럼 실제 효과가 적용되었다고 오해할 문구는 사용하지 않는다. 기존 이야기 기록을 지우지 않고 AddMessage로 추가한다. 한국어 fallback·Fade·스크롤·발화자 구조를 유지한다.

EffectKind → 현지화 가능한 표시명 매핑은 한 표현 경계에서 관리한다. 새 효과 추가 시 여러 UI switch를 동시에 수정해야 하는 구조를 피하되 현지화 시스템 전면 교체는 하지 않는다. 미지원 효과를 정상 공격·회복으로 표시하지 않는다.

## 호환성과 자산 적용

기존 코드 호출자와 숫자 기반 테스트를 함께 갱신한다. 필요하다면 명시적인 이전 어댑터를 두되 숫자 하나를 효과로 자동 추정하는 장기 API는 만들지 않는다.

알려진 기본 임시 설정은 위 표로 전환한다. 사용자 커스텀 주사위 설정이 발견되면 해당 숫자의 효과 매핑을 임의로 정하지 말고 확인한다. 재실행 가능한 이전 처리를 사용하고 이미 전환된 데이터를 다시 덮어쓰지 않는다. FormerlySerializedAs만으로 int[]를 구조체 목록으로 변환할 수 있다고 가정하지 않는다.

기존 운영 저장 포맷은 변경하지 않는다. Editor 미저장 변경과 Prefab Override를 보존하고 필요한 자산만 수정한다. 컴파일·OnValidate·리로드에 자동 재생성을 연결하지 않는다. 생성기와 저장된 설정이 일치하는지 확인한다.

## 검증 기준

1. D4/D6/D8의 효과·수치가 표와 일치하고 면별 편집·런타임 교체가 가능해야 한다.
2. 가짜 난수로 각 면을 지정하여 효과·수치·면 식별자가 정확한지 확인한다. 중복 면도 독립적으로 선택되어야 한다.
3. 외부 면 선택 경로에서 동일한 결과를 만들고 난수가 소비되지 않는지 검증한다.
4. 범위 밖 수치, 미지원 효과, 빈 목록, 잘못된 면 인덱스와 실패 후 상태 보존을 확인한다.
5. 원본 배열 변경·다른 주사위 수정·굴림 후 면 변경이 기존 결과에 영향을 주지 않아야 한다.
6. 세션 보유·캐릭터 변경·Scene 재진입·재실행 초기화 정책을 유지한다.
7. 실제 TMP_MainScene에서 버튼을 눌러 각 주사위의 효과와 수치가 한 번씩 추가되고 기존 기록이 남는지 확인한다. 플레이어·적 체력 및 저장 데이터가 변하지 않아야 한다.
8. 관련 Gameplay/Application 테스트, 컴파일과 실제 한국어 표시를 검증한다. 3D 물리·실제 효과 실행은 미구현 범위임을 명시한다.
