# 다음 노드 선택 카드 UI

## 목적과 범위

기존 다음 노드 선택 버튼을 재사용 가능한 카드 Prefab으로 교체한다. 사용자가 선택한 배치는 세로형 카드의 가로 나열이며 좁은 화면에서는 줄바꿈한다. 기본 후보는 현재처럼 3개지만 생성된 후보 개수에 대응한다.

이번에는 실제 카드 UI, 선택 연결, 선택적 이미지 설정과 향후 연출을 위한 계층·수명 경계를 구현한다. 회전·이동·ease-in/out 애니메이션과 모자이크·노이즈 셰이더의 실제 제작은 추후 범위다. 새로운 Tween 패키지나 전체 화면 효과 프레임워크를 추가하지 않는다. 노드 확률·탐험 규칙·체력·저장·회복 및 강화 미구현 정책은 변경하지 않는다.

## 사전 확인 및 현재 상태

AGENTS.md, DOCS/README.md, DOCS/architecture/exploration-node-tree.md, DOCS/architecture/flexible-layout-panel.md, DOCS/architecture/asset-management.md를 읽는다. CodeGraph로 호출자를 탐색하고 실제 소스로 확인한다.

현재 `ExplorationRunController`에는 choiceButtons와 choiceLabels 배열이 있고 EnsureChoiceCapacity가 첫 버튼을 복제한다. ShowChoices가 종류 이름을 채우며 SelectChoice는 인덱스로 현재 후보를 조회한다. Unbind는 RemoveAllListeners를 사용한다. 카드 전환 시 이 영역을 확인하고 명시적인 카드 바인딩·구독 해제로 개선한다. 기존 외부 이벤트까지 지우지 않는다.

## 카드 계층과 소유권

다음은 권장 계층이다. 동일 역할의 기존 컴포넌트는 재사용한다.

```text
CardRoot                       부모 Layout이 크기·위치를 관리
├── 안정적인 입력 영역          Button/선택 포커스
└── MotionRoot                 향후 이동·회전·확대 연출
    └── VisualRoot             외형과 공통 알파
        ├── Background
        ├── ArtworkViewport
        │   └── Artwork        선택적 Sprite
        ├── Title
        ├── Description
        ├── StatusBadge        미구현 등
        ├── Border/FocusVisual
        └── EffectOverlay      선택적 장식 효과
```

Layout이 제어하는 CardRoot를 Animator나 Tween이 직접 움직이지 않게 한다. MotionRoot는 재바인딩 시 기본 회전·위치·스케일로 복구한다. 카드가 회전할 수 있다는 이유만으로 3D 물리 오브젝트로 전환하지 않는다.

이번 기본 입력 영역은 Layout 슬롯에 유지한다. 향후 카드가 크게 이동하거나 뒤집히는 연출에서는 화면과 입력 영역이 어긋나지 않도록 연출 중 입력 차단 또는 별도 hit-test 정책을 적용할 수 있어야 한다. 효과 이미지들은 RaycastTarget을 꺼서 클릭을 가로채지 않게 한다.

## 데이터와 선택

카드 View는 표시명, 설명, 상태 문구, 선택적 이미지와 선택 가능한 상태를 받는다. 전투 시작이나 후보 생성을 직접 실행하지 않는다. 노드 종류와 외형 설정은 분리하고, 새로운 종류가 들어오면 표시 데이터를 공급하는 경계에서 확장한다.

각 바인딩은 Run ID, ChoiceSet ID, Node ID 또는 그와 동등한 유효성 식별 정보를 보존한다. 배열 인덱스만으로 나중 시점의 현재 후보를 선택하지 않는다. 오래된 카드·콜백은 새 후보를 선택할 수 없어야 한다.

선택은 클릭·터치·Submit으로 기존 단일 선택 동작을 수행한다. Hover나 포커스만으로 노드를 확정하지 않는다. 처리 중 모든 후보의 추가 선택을 막고, 성공하면 기존 노드 진입 흐름을 따른다. 애니메이션 완료 이벤트가 논리 선택을 다시 실행하지 않도록 경계를 둔다.

카드 수는 실제 CurrentChoices에 맞춘다. 불필요한 대규모 풀링 프레임워크는 만들지 않되 재사용한다면 바인딩·구독·이미지·효과 상태를 완전히 초기화한다. Unbind는 자신이 등록한 이벤트만 제거한다. UI 재표시가 후보 재추첨이나 트리 기록 변경을 일으키면 안 된다.

## 기본 외형과 반응형 배치

세로 카드의 제목·설명·선택 상태가 명확히 보여야 한다. 전투와 회복 및 강화의 구분은 색상뿐 아니라 텍스트로도 제공한다. 미구현 카드는 선택 가능하며 `미구현` 상태와 기존 계속 안내를 유지한다.

개발자가 카드 목표 크기, 간격, 패딩을 설정할 수 있게 한다. 실제 가용 너비를 기준으로 가로에 들어가는 수를 계산하고 나머지는 다음 행에 놓는다. 그룹은 가로 중앙에 배치하되 순서와 키보드 탐색은 후보 순서를 유지한다. 카드의 세로 비율과 읽을 수 있는 글자 크기를 유지하며 좁은 화면에서 단순 전체 축소를 기본 대안으로 쓰지 않는다.

화면 높이를 넘으면 세로 스크롤로 모든 카드에 접근할 수 있게 한다. 수평 스크롤은 이번에 선택한 방식이 아니다. Safe Area, Canvas Scaler와 실제 부모 Rect를 고려한다. 그림·제목·설명은 긴 한국어/영문과 확대 글자에서도 겹치지 않게 배치한다.

처음 후보가 표시될 때 첫 유효 카드에 포커스를 주고 행 간 이동을 결정적으로 구성한다. 크기 변경 때 유효한 현재 선택은 가능한 한 유지한다. 선택 대기에서는 Cancel이 임의 노드를 선택하거나 탐험을 완료하지 않게 한다.

## 이미지와 효과 확장

- Artwork Sprite는 선택 사항이다. 없으면 중립적인 대체 표시 또는 이미지 영역 축소 정책을 일관되게 적용하며 제목·입력은 유지한다. 이미지가 없어도 카드가 완전하게 동작해야 한다.
- 이미지 비율을 보존하고 Fit/Crop 정책을 명확히 한다. TMP 텍스트를 이미지에 구워 넣지 않는다. 새로운 아트가 없어도 기본 배경·텍스트로 완료할 수 있다.
- 향후 비동기 이미지 로드를 연결한다면 기존 Provider·Lease 수명을 활용한다. 재바인딩·Scene 종료 시 취소·해제하고 늦게 완료된 이전 노드 이미지가 새 카드에 적용되지 않게 한다.
- Background, Artwork, Border와 텍스트의 효과 적용 대상을 분리한다. Artwork용 Material 하나로 TMP까지 처리된다고 가정하지 않는다. Overlay는 모자이크가 하위 전체 렌더링을 자동 처리하는 장치가 아니므로 전체 카드 후처리는 추후 별도 설계 대상이다.
- 공유 Material을 런타임에 직접 변경해 다른 카드까지 바꾸지 않는다. 개별 인스턴스가 필요하면 생성·재사용·해제 책임을 명시한다. 마스킹·Canvas 알파·TMP fallback을 유지할 수 있는 UGUI 호환 경계를 사용한다.
- 향후 연출은 진입·포커스·확정·퇴장 상태를 받을 수 있어야 한다. 논리 확정과 시각 연출 완료를 구분한다. 취소·재활성화·재사용 시 남은 Tween/Animator 상태가 없어야 한다.
- 이번 기본 연출은 정적 상태다. 효과가 없어도 선택 가능하고, 추후 모션 감소·효과 비활성에서도 게임 정보가 사라지지 않도록 한다.

## 적용·호환성·검증

Editor 컴파일·미저장 변경·Prefab Override를 확인하고 신규 카드 Prefab의 필수 참조를 완성해 저장한다. 기존 버튼 배열에서 카드 목록으로 바꾸면 Scene 연결과 생성기를 함께 이전한다. 이전 필드를 제거하기 전에 사용자 구성과 직렬화 데이터 영향을 확인한다.

1. 최초 후보·전투 완료 후 후보·Scene 재연결에서 정확한 카드 수와 종류가 표시되는지 확인한다.
2. 카드 선택이 해당 Node ID로 한 번만 전달되고 미선택 기록·체력 연속성이 기존과 동일한지 검증한다.
3. 미구현 카드 선택 후 안내·계속이 유지되는지 확인한다.
4. 1/3/5개 후보, 충분한 폭/좁은 폭/부족한 높이에서 줄바꿈·중앙 배치·세로 접근성을 확인한다.
5. 이미지 없음·있음·긴 설명·한국어 fallback·포커스·비활성 상태를 실제 Game View로 확인한다.
6. 재사용·이전 콜백·중복 입력·비활성화·Scene 파괴에서 잘못된 선택이나 구독 누수가 없는지 테스트한다.
7. MotionRoot에 수동으로 회전·스케일을 적용해 CardRoot의 Layout 계산과 충돌하지 않는지 확인하고 기본값으로 복구한다. 이것을 실제 애니메이션 구현 완료로 보고하지 않는다.
8. 관련 테스트와 컴파일, 실제 TMP_MainScene 선택 흐름을 검증하고 넓은/좁은 화면 캡처를 제공한다. 실제 기기 미검증은 명시한다.
