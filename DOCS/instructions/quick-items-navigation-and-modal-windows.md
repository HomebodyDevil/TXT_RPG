# 빠른 아이템 슬롯, 메뉴 패널과 모달 창 구현 지침

## 목적과 확정 수준

이 문서는 구현 담당 AI에게 전달하는 작업 명세이며 구현 완료를 의미하지 않습니다. TMP_MainScene의 ActionGridPanel을 빠른 아이템 사용에 연결하고, 시스템·가방·Status 버튼 패널 및 공통 모달 호스트를 게임 실행 경로에 통합하십시오. 클래스와 인터페이스 선언만 추가하는 것으로 완료하지 마십시오.

요구사항과 위치는 잠정적입니다. 아래 기본 정책은 초기 구현을 위한 제안이며 제품의 영구 규칙이 아닙니다. 정책을 설정과 명확한 책임 경계로 분리하되 임의 스크립트 엔진이나 범용 프레임워크를 만들지 마십시오.

## 사전 조사와 확인한 현재 경계

AGENTS.md와 DOCS/README.md를 읽고 architecture/action-grid-panel.md, flexible-layout-panel.md, player-session.md, character-domain.md, character-status-ui.md, asset-management.md, scene-transition.md 및 development/workflows.md를 확인하십시오. CodeGraph가 있으면 먼저 호출 관계를 조사하고 실제 코드와 직렬화 자산으로 확인하십시오.

## 범위와 임시 기본 정책

이번 범위는 빠른 슬롯 상태·등록·해제·사용, 실제 수량과 사용 결과를 제공하는 최소 아이템 소유 모델, 메뉴 버튼 패널, 단일 모달 호스트, 각 메뉴의 교체 가능한 기본 페이지, 씬 통합과 저장 호환성입니다.

가방은 소유 아이템 목록에서 슬롯 번호를 선택해 등록하는 최소 기능만 제공합니다. 무게, 장비, 희귀도, 정렬 규칙, 제작, 상점, 드래그 앤 드롭은 후속 범위입니다. Status는 현재 제공되는 활성 캐릭터의 체력과 공격력을 읽기 전용으로 표시합니다. 시스템 페이지는 기존 설정 서비스가 있으면 이를 연결하고, 없으면 미구현 안내와 닫기를 제공하십시오. 동작하지 않는 설정 토글을 실제 기능처럼 표시하지 마십시오.

| 항목 | 초기 기본값 | 변경 지점 |
| --- | --- | --- |
| 메뉴 위치 | ActionGridPanel 아래 | Inspector 레이아웃 프리셋 |
| 빠른 슬롯 순서 | 등록 위치 유지 | 슬롯 Packing 정책 |
| 소모품 참조 | Definition ID | 등록 대상 모델과 해석 서비스 |
| 중복 등록 | 동일 대상의 중복 등록 거부 | 등록 정책 |
| 수량 0 | 등록 유지, 사용 비활성 | 고갈 정책 |
| 빠른 사용 | Use 명령 직접 실행 | 직접 사용/컨텍스트 메뉴 설정 |
| 활성 창 | 한 번에 하나 | 창 관리 서비스 |
| 같은 창 다시 요청 | 기존 창 유지 및 포커스 | 창 열기 정책 |

| 게임 일시 정지 | 자동 변경하지 않음 | 별도 게임 흐름 정책 |

정책 변경이 저장 형식에 영향을 주는 경우 명시적으로 버전과 마이그레이션을 적용하십시오.

## 책임과 제안 타입

아래 이름과 새 폴더는 제안입니다. 기존 관례와 중복 여부를 확인하고 최종 경로를 문서화하십시오.

| 제안 타입 | 책임 및 계층 |
| --- | --- |
| ItemDefinition | Content의 ID, 이름 키, 아이콘 ID와 지원 효과 정의입니다. 런타임 수량은 보관하지 않습니다. |
| InventoryState | Gameplay의 소유 수량과 변경 이벤트를 소유합니다. UI를 참조하지 않습니다. |
| QuickItemSlotState / QuickItemLoadout | Gameplay의 슬롯 번호와 대상 참조를 소유합니다. 아이템을 복제하지 않습니다. |
| QuickItemService | Application에서 등록 검증, 해제와 사용 흐름을 조합합니다. |
| IItemUseService | 사용 직전 검증과 실제 효과·소모의 실행 결과를 제공합니다. |
| QuickItemGridPresenter | 상태를 ActionGridEntry로 변환하고 기존 메뉴·명령 인터페이스와 연결합니다. |
| GameMenuPanel | 구성된 버튼의 의미 ID와 활성 상태를 표시하고 선택 요청을 전달합니다. |
| GameWindowService | 페이지 등록, 열기·닫기, 전환 취소와 입력 소유권을 관리합니다. |
| ModalWindowHost | 딤 배경, 제목, 닫기 버튼, 콘텐츠 컨테이너와 로딩·오류 상태를 표시합니다. |
| WindowPage / 페이지 Presenter | 시스템, 가방, Status의 개별 화면과 데이터 바인딩을 담당합니다. |

Unity UI의 기반 컴포넌트와 게임 규칙을 분리하십시오. Application이 Gameplay, Content와 UI를 연결하며 Gameplay에 UI 또는 Addressables 의존성을 추가하지 마십시오. 기존 PlayerSession은 플레이어 상태의 소유자로 유지합니다. 각 버튼이나 창이 세션을 새로 생성해서는 안 됩니다.

## 빠른 슬롯 등록과 실행

빠른 슬롯은 소유 아이템을 가리키는 단축 참조입니다. 등록·해제는 수량을 늘리거나 줄이지 않습니다. 최소 구현에서는 소모품 Definition ID로 소유 수량을 해석하고, 향후 개별 장비를 지원할 때 Instance ID와 Definition ID를 혼용하지 않도록 대상 종류를 명시하십시오.

- 슬롯 번호는 0부터 시작하는 안정된 위치입니다. 아이템 ID와 UI Entry ID를 분리하십시오. 동일 아이템의 여러 등록을 허용하는 후속 정책에서도 Entry ID 충돌이 없어야 합니다.
- 슬롯 용량은 인벤토리 용량이나 열 수와 별개입니다. 화면 너비가 변해도 등록 위치와 용량은 변하지 않습니다.
- 기본은 PreserveSlots이며 중간 슬롯 해제 후 다른 슬롯이 이동하지 않습니다. 공통 ActionGridPanel의 기존 CompactForward 기본 동작을 모든 사용처에서 변경하지 마십시오.
- 빈 슬롯도 Capacity만큼 표시하십시오. Presenter가 빈 항목을 제거해 인덱스를 압축하지 않도록 기존 API를 점검하십시오.
- 등록은 범위, 소유 여부, 지원되는 사용 항목인지 검증합니다. 잘못된 등록은 기존 상태를 보존하고 실패 사유를 반환합니다.
- 용량 축소로 등록된 슬롯이 잘리면 기본적으로 거부합니다. 명시적 해제 정책을 추가하더라도 도메인 아이템을 삭제하지 마십시오.
- 가방 페이지에 슬롯 번호 선택과 등록·해제 조작을 제공하여 터치 및 컨트롤러로 동일 기능을 수행할 수 있게 하십시오.
- 빠른 사용은 명시적인 Use 명령 ID로 실행합니다. 현재 ExecuteDefaultAction의 첫 활성 명령 규칙을 사용할 경우 제거 명령이 먼저 실행되지 않도록 전용 메뉴 제공자와 검증을 두십시오.
- 실행 직전에 소유 수량, 대상 캐릭터, 사용 가능 상태를 다시 확인하십시오. UI의 IsEnabled는 실행 권한의 근거가 아닙니다.
- 이중 클릭과 터치 중복으로 초과 소모되지 않도록 요청을 직렬화하거나 중복 실행을 차단하십시오.
- 효과 적용과 수량 차감은 하나의 성공 단위입니다. 실패 시 수량이 차감되지 않아야 합니다. 취소는 확정 전까지만 적용하며 확정 이후 취소를 성공 취소로 보고하지 마십시오.
- 최소 검증 항목으로 회복 소모품 한 종류를 구현해 활성 캐릭터의 기존 HealthState 회복 경로를 사용하십시오. 최대 체력에서는 소비하지 않는 정책을 기본으로 하고 실패 이유를 표시합니다.
- 현재 캐릭터가 실행 중 변경될 수 있으므로 요청의 대상 Instance ID를 확정하고 검증하십시오. 다른 캐릭터에게 조용히 적용하지 마십시오.
- 수량과 체력 변경 이벤트가 가방·빠른 슬롯·열린 Status에 반영되어야 합니다. 페이지를 닫아도 게임 상태는 유지됩니다.

테스트용 소모품 지급은 명시적인 데모 설정 또는 테스트 경로로 제공하십시오. 운영 저장 데이터에 임의로 지급하지 마십시오. 아이템이 없으면 정상적인 빈 목록을 표시합니다.

## 메뉴 배치와 화면 구성

메뉴 ID는 system, inventory, status 같은 안정된 값으로 구성하고 GameObject 이름이나 버튼 표시 문자열을 라우팅 키로 쓰지 마십시오. 버튼 순서, 표시 여부, 아이콘과 현지화 키는 직렬화 설정으로 관리하십시오. 미등록 페이지는 버튼 비활성 또는 명시적인 미구현 페이지로 처리합니다.

두 위치를 교체 가능한 화면 레이아웃 프리셋으로 제공하십시오.

- BetweenActionAndCharacter: 현재 실제 씬의 상대 배치를 조사하여 ActionGridPanel과 CharacterDisplayPanel 사이에 배치합니다. 기존 StoryTextPanel이나 다른 요소를 제거하지 마십시오.
- BelowActionGrid: ActionGridPanel과 GameMenuPanel을 세로 중첩 컨테이너로 구성합니다. 초기 기본 위치는 이 방식입니다.

FlexibleLayoutPanel과 FlexibleLayoutItem으로 배분하고 상위 레이아웃이 제어하는 RectTransform 위치를 버튼 코드에서 직접 쓰지 마십시오. 부모가 이미 가로 배치이고 해당 두 요소가 이웃이 아니면 무조건 직계 자식 사이에 끼워 넣지 말고 적절한 중첩 컨테이너를 구성하십시오. 프리셋별 실제 계층을 문서화하십시오.

위치 변경 시 같은 버튼·Presenter 인스턴스를 재배치하고 리스너 중복이나 참조 유실을 방지하십시오. 자동 Breakpoint 전환은 선택적 후속 기능이며 이번에는 개발자가 두 프리셋을 명시 선택할 수 있으면 충분합니다.

## 공통 모달 호스트

하나의 호스트에 별도 페이지 프리팹을 교체하여 표시하십시오. 모든 기능을 한 MonoBehaviour에 switch로 구현하지 마십시오. 기본 상태는 Closed, Opening, Open, Closing이며 실패와 취소 경로를 정의하십시오.

```text
Scene UI Root
├── 기존 화면 콘텐츠 및 GameMenuPanel
└── ModalLayer
    └── ModalWindowHost
        ├── Dimmer / InputBlocker
        └── WindowFrame
            ├── Header / CloseButton
            ├── PageContentRoot
            └── LoadingOrError
```

- 호스트는 그리드와 FlexibleLayoutPanel의 마스크 밖에 두고 Safe Area를 고려합니다. Scene 전환 Overlay보다는 아래에 렌더링합니다.
- 호스트와 페이지 UI는 기본적으로 콘텐츠 Scene 수명입니다. 영속 세션은 데이터만 소유합니다. 버튼 위치 변경으로 모달 좌표계가 바뀌지 않아야 합니다.
- 페이지에 Prepare/Show/Hide/Dispose 또는 동등한 수명 계약을 제공하십시오. 준비 완료 전에는 로딩 상태를 표시합니다.
- A 열기 중 B를 요청하면 이전 준비를 취소하거나 최신 요청만 반영하십시오. 닫힌 뒤 늦은 로드가 도착해 페이지를 다시 열지 않게 하십시오.
- 같은 페이지 중복 생성, 두 모달 동시 표시 및 이벤트 중복 구독을 방지하십시오. 초기는 닫을 때 페이지를 정리하는 단순 정책이면 충분하며 무제한 캐시를 만들지 마십시오.
- 기존 자산 공급자와 Lease를 재사용할 수 있어야 합니다. 직접 프리팹 참조부터 시작해도 되지만 새 Addressables 병렬 체계를 만들지 마십시오. 실패 시 오류와 재시도 또는 닫기 경로를 제공하십시오.
- 닫기, 취소, 로딩 실패 및 Scene 해제 시 입력 차단, 구독, 애니메이션과 임시 자원을 반드시 정리하십시오.
- 모달 표시 중 뒤쪽 포인터, Submit, 빠른 아이템 단축키와 게임 입력을 차단하십시오. Raycast 차단만으로 키보드 명령까지 차단됐다고 판단하지 마십시오.
- Navigate/Submit/Cancel 의미 입력을 사용하고, 최초 선택·포커스 제한·닫힌 뒤 호출 버튼으로 복원을 구현하십시오. 호출 버튼이 없어졌으면 유효한 기본 대상으로 복원합니다.
- Cancel은 가장 위의 일시 UI부터 처리합니다. 열린 ActionContextMenu와 모달이 한 번의 입력으로 동시에 동작하지 않게 하십시오. 모달을 열기 전 기존 컨텍스트 메뉴를 닫습니다.
- Time.timeScale을 직접 0으로 바꾸지 마십시오. 일시 정지 정책이 필요하면 기존 게임 흐름 서비스에 위임하고 해제 소유권을 분리합니다. 전환 효과와 게임 입력 차단이 겹쳐도 한쪽 닫기가 다른 차단을 해제하지 않게 하십시오.
- 텍스트 확대, 긴 현지화 문구, 작은 화면에서 페이지가 스크롤되고 닫기 버튼이 접근 가능해야 합니다. 효과 끄기 및 모션 감소 설정을 고려합니다.

## 저장과 복원

소유 수량과 빠른 슬롯 등록은 플레이어 데이터입니다. UI나 ScriptableObject 원본에 변경값을 기록하지 마십시오. 기존 저장 경로에 버전이 있는 DTO와 마이그레이션을 통합하고 슬롯 번호, 안정적인 대상 ID, 수량만 기록하십시오. Sprite, GameObject, 페이지 프리팹 및 델리게이트는 저장하지 않습니다.

이전 저장에 새 필드가 없으면 빈 소유 목록과 기본 용량의 빈 슬롯으로 복원하고 기존 캐릭터 상태를 보존하십시오. 알 수 없는 아이템 ID는 다른 아이템으로 대체하지 말고 미해결 참조로 보존하여 비활성 표시하십시오. 잘못된 수량이나 중복 슬롯 등 손상 데이터는 기존 저장 오류 정책에 맞춰 진단하고 자동 새 게임으로 덮어쓰지 마십시오.

슬롯과 수량 스냅샷은 일관되게 저장해야 합니다. 페이지 열림 여부나 임시 로딩 상태는 저장하지 않습니다. 향후 가방 규칙 변경에 영향을 받는 부분과 마이그레이션 방식을 문서화하십시오.

## 구현 순서와 검증

1. 기존 경계를 확인하고 최소 도메인 상태, 등록·사용 서비스와 저장 이전을 구현합니다.
2. ActionGridPanel 전용 Presenter로 빈 슬롯, 등록, 사용 및 수량 갱신을 연결합니다.
3. 메뉴 패널과 모달 호스트 및 기본 페이지를 구현합니다.
4. 가방 목록에서 등록하고 빠른 슬롯으로 사용하여 체력·수량이 변하는 종단 경로를 완성합니다.
5. 두 레이아웃 프리셋과 TMP_MainScene 통합, 반복 실행 가능한 생성·이전 절차를 제공합니다.
6. 테스트와 실제 UI 검증 후 문서를 갱신합니다.

핵심 수용 조건은 다음과 같습니다.

- 보유한 회복 아이템을 지정 슬롯에 등록하고 사용하면 수량은 한 번 감소하고 체력은 규칙대로 회복됩니다. 실패와 확정 전 취소는 소모하지 않습니다.
- 중간 슬롯 해제 후 다른 슬롯 위치가 유지되고 수량 0에서는 등록을 유지한 채 사용 불가를 표시합니다.
- 이중 실행, 무효 ID, 최대 체력, 슬롯 범위 초과, 등록 중 용량 축소를 검사합니다.
- 저장·재시작 및 이전 버전 저장에서 캐릭터·수량·등록이 일관되게 복원됩니다.
- 메뉴 위치를 바꿔도 동일한 페이지가 열리고 열기·닫기 반복 후 중복 리스너가 없습니다.
- 빠른 열기·교체·닫기, 페이지 로드 실패, Scene 전환 중 취소 후 입력 차단이 남지 않습니다.
- 마우스·터치·컨트롤러, 좁은 화면, Safe Area와 긴 문구를 가능한 환경에서 검증합니다.
- 모달 뒤의 슬롯은 포인터와 단축키 모두로 실행되지 않으며, 닫은 뒤 포커스가 복원됩니다.

실제 Edit Mode/Play Mode 테스트 및 관련 어셈블리 컴파일을 수행하십시오. 기기에서 수행하지 않은 검증은 명시하십시오. 검증 데이터와 운영 데이터를 분리하고 현재 사용자 씬·프리팹 Override를 보존하십시오. 생성기는 반복 실행해도 중복 패널이나 컴포넌트를 만들지 않아야 합니다.
