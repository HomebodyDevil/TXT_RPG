# Actions 슬롯 간격과 선택 가능한 표시 방식

## 1. 목적과 확정 사항

메인 화면 Actions의 슬롯이 지나치게 밀집되어 보이는 문제를 개선한다. 셀 크기, 셀 사이 간격과 외곽 여백을 함께 조정하고, 개발자가 목적에 맞게 표시 방식을 선택할 수 있도록 한다. 이 문서는 후속 구현 지침이며 실제 코드·자산 적용이나 화면 검증 완료 기록이 아니다.

사용자가 확정한 방향은 다음과 같다.

- 운영 Actions의 기본값은 **균형형 간격 조절**이다. 셀 크기에 적절한 상한을 두고 간격·여백을 확보하며, 좁은 화면에서는 열 수를 줄인다.
- 새 기본값은 **메인 화면 Actions에만 적용**한다. Bag과 다른 Grid는 기존 표시를 유지하며, 개발자가 필요할 때 개별적으로 전환할 수 있게 한다.
- 개발자는 균형형, 남는 너비를 간격에 배분하는 방식, 적은 열·큰 슬롯 방식과 기존 수동 설정을 선택할 수 있어야 한다.
- 이번 작업은 표시 정책 변경이다. 퀵 슬롯 개수·번호·등록 아이템·게임 규칙·저장 데이터는 변경하지 않는다. 플레이어용 설정 메뉴를 추가하지 않는다.

## 2. 검토한 선택지와 장단점

| 선택지 | 동작 | 장점 | 고려 사항 |
| --- | --- | --- | --- |
| 균형형 간격 조절: 선택한 기본값 | 셀 최소·최대 크기와 고정 간격·외곽 여백을 함께 설정한다. 좁으면 열 수를 줄인다. | 슬롯 경계가 분명하고 배치가 안정적이다. | 넓은 영역에 남는 공간을 모두 채우지는 않는다. |
| 남는 너비를 간격에 배분 | 셀 크기를 유지하고 가로 잔여 공간을 슬롯 사이에 배분하되 간격 상한을 둔다. | 넓은 영역을 활용하면서 셀이 과도하게 커지지 않는다. | 화면 너비에 따라 슬롯 사이 거리가 달라진다. |
| 적은 열·큰 슬롯 | 기본 최대 열 수를 줄이고 셀을 크게 표시한다. | 아이콘 식별과 터치 조작이 편하다. | 행 수와 세로 스크롤이 늘어날 수 있다. |
| 수동 설정 | 기존 Layout Mode, 크기·간격·Padding·정렬을 직접 설정한다. | 기존 화면을 재현하고 세부 조정할 수 있다. | 개발자가 해상도별 결과를 직접 점검해야 한다. |

단순히 아이콘 그림만 줄이면 클릭 영역 사이의 간격은 바뀌지 않는다. 반대로 Spacing만 늘리면 현재 계산에서는 셀 너비가 줄어들 수 있다. 따라서 클릭 가능한 셀의 크기, 실제 그림의 크기, 셀 간격과 부모가 배정한 공간을 구분해서 진단한다. 슬롯을 숨기거나 줄여 밀집감을 해결하지 않는다.

## 3. 선행 조사와 확인한 현재 구조

먼저 `AGENTS.md`, `DOCS/README.md`, `DOCS/architecture/action-grid-panel.md`, `DOCS/architecture/quick-items-and-game-windows.md`, `DOCS/development/workflows.md`를 읽는다. 기존 아이콘 크기 정책은 `DOCS/instructions/action-grid-ratio-capped-sizing.md`를 참고하되 실제 구현과 저장 자산을 우선한다.

시작 시 Git 상태와 관련 diff를 확인하고 기존 사용자 작업을 보존한다. `.codegraph/`가 있으면 호출·영향 분석에 먼저 사용한 뒤 소스·Prefab·Scene과 대조한다. 임의로 재색인하지 않는다.

작성 시 확인한 사항은 다음과 같다.

- 운영 `TMP_MainScene.unity`에는 `ActionGridPanel.prefab` 인스턴스의 fixedColumns=6, spacing=(10,10), minimumCellSize=(10,10), maximumCellSize=(200,200), initialCapacity=16 override가 있다. 이는 저장된 설정이며 실행 중 최종 셀 크기·표시 슬롯 수를 측정한 결과가 아니다.
- 공용 Prefab은 최대 5열, 최소 72×72, 최대 128×128, 간격 8×8을 저장하고 있어 운영 override와 다르다. Scene 값만 보고 공용 기본값까지 변경하지 않는다.
- `ActionGridPanel.ApplyLayout`은 Viewport 폭과 Padding, 열 수, Spacing으로 셀 너비를 구한 뒤 최소·최대 범위로 제한한다. 현재 비-ExactColumns 모드는 남는 너비를 우선 셀 크기에 사용한다. 명시적인 잔여 너비 간격 배분 정책은 없다.
- `ActionGridLayoutMode`에는 FixedColumns, AdaptiveCellSize, ExactColumns가 있다. FixedColumns는 최대 열 수를 뜻하며 폭이 부족하면 열 수를 줄인다. ExactColumns는 기존 고정 열 의미를 유지해야 한다.
- 셀 안의 Icon·EmptySlot은 `ActionGridCell`이 별도로 크기를 관리한다. 배치용 Cell 루트와 그림 크기 설정은 서로 다른 책임이다.
- `QuickItemGridPresenter`는 빈 슬롯 채움·PreserveSlots·기본 행동 실행 정책과 플레이어 퀵 슬롯 데이터를 공급한다. initialCapacity만 보고 실제 운영 슬롯 개수를 바꾸면 안 된다.
- 실제 실행 화면에서 밀집감을 유발하는 최종 원인은 아직 측정하지 않았다. 최소 크기 10이나 최대 크기 200만을 확정 원인으로 단정하지 않는다.

## 4. 개발자가 선택하는 설정 계약

기존 패널 Inspector에 이해하기 쉬운 표시 방식 선택을 제공한다. 실제 enum·필드·메서드명은 현재 관례에 맞춰 정하되, UI에는 각 방식의 결과와 사용되는 값의 단위를 설명한다. 이 네 선택지를 단순한 문서 제안으로만 남기지 않고 실제 선택 가능한 동작으로 구현한다.

표시 방식은 슬롯 배치 알고리즘 전체를 복제하는 별도 Grid 시스템이 아니다. 균형형과 적은 열·큰 슬롯은 공통 계산기의 설정 묶음을 사용하고, 공간 배분 방식만 필요한 간격 계산을 추가한다. 현재 값·원본 설정·계산 결과의 소유권을 분리하며 중복 설정이 서로 덮어쓰지 않게 한다.

- 기존 직렬화 자산은 수동 설정을 유지한다. 신규 선택 필드의 누락 기본값은 기존 외형을 재현해야 한다. 기존 enum 번호와 API 위치 인수 의미를 바꾸지 않는다.
- 최소·최대 셀 크기, 최대 열 수, 가로·세로 간격, 외곽 Padding과 정렬을 개발자가 조절할 수 있게 한다. 공간 배분 방식에는 목표 셀 크기와 최소·최대 가로 간격을 제공한다.
- 방식별 조정값과 수동값을 분리하여 선택지를 오갈 때 사용자가 편집한 수동값이 사라지지 않게 한다. 매 OnEnable·OnValidate에서 원래 추천 수치를 강제로 덮어쓰지 않는다.
- Inspector에서 실제 적용된 열 수·셀 크기·간격·필요 높이와 공간 부족 여부를 확인할 수 있게 한다. 숨은 자동 변경은 진단 가능한 값으로 드러나야 한다.
- 명시적인 런타임 설정 변경 경로를 제공하거나 기존 API를 일관되게 확장한다. 방식 전환·활성화·해상도 변경 시 같은 계산을 사용한다.
- 외부 설정을 전달하는 기존 ConfigureLayout 호출은 수동 설정 계약을 유지한다. 새 방식으로 전환하는 API는 명시적으로 구분한다. Bag은 InventoryGameWindowPage와 GridContentLayoutSettings가 설정 원본이므로 패널 Inspector에서만 바꾼 값을 Refresh가 덮어쓰는 상태를 만들지 않는다. Bag에서 개발자가 새 방식을 선택할 수 있도록 해당 원본 설정에 최소한의 명시적 선택을 연결하되, 저장된 기본값·기존 호출자는 계속 수동 설정을 사용한다.
- 새 전역 Manager나 플랫폼별 분기, 플레이어 저장 옵션은 도입하지 않는다. 공유 프로필을 도입할 실익이 없다면 인스턴스별 직렬화 설정으로 충분하다.

## 5. 방식별 계산 요구사항

### 균형형: 운영 Actions 기본값

기존 FixedColumns의 최대 열 정책을 사용하고 셀 최소·최대 크기, Spacing과 Padding을 함께 조정한다. 폭이 부족하면 셀을 무리하게 압축하지 말고 열 수를 줄인다. 높이가 부족하면 기존 세로 스크롤로 모든 슬롯에 접근할 수 있어야 한다.

초기 조정 후보는 셀 56~72 UI 단위, 간격 14~18 UI 단위, 외곽 여백 12~16 UI 단위와 최대 6열이다. 이는 확정된 완성 수치가 아니라 실제 Viewport·Canvas Scaler·그림·터치 영역을 측정하기 위한 출발 범위다. 최종값은 대표 해상도에서 비교 후 정하고 문서와 결과 보고에 기록한다. 물리 픽셀이나 보편적인 터치 크기 보장으로 표현하지 않는다.

셀 상한에 도달한 뒤 남는 공간은 기존 Grid Alignment에 따라 배치한다. 가로 간격은 정한 값으로 유지하고 넓은 화면을 채우려고 셀을 계속 키우지 않는다. 기존 세로 배치 정책은 유지한다.

### 남는 너비를 간격에 배분

Padding과 실제 스크롤바 점유 폭을 제외한 Viewport 내부 폭을 W, 최종 열 수를 C, 셀 너비를 S, 가로 간격 범위를 Gmin~Gmax라고 할 때 C>1이면 다음처럼 계산한다.

```text
G = clamp((W - C × S) / (C - 1), Gmin, Gmax)
```

열 수는 목표 셀 크기와 최소 간격으로 들어가는 수를 먼저 구하고 설정한 최대 열 수를 넘지 않게 한다. 잔여 공간이 음수인 상태를 음수 간격이나 셀 겹침으로 해결하지 않는다. C=1일 때 0으로 나누지 않고 기존 가로 정렬을 적용한다. 간격 상한 이후 남는 폭은 외부 정렬 여백으로 둔다.

세로 간격은 별도 설정으로 유지하며 높이를 채우려고 행 간격을 무한히 벌리지 않는다. 전체 행에 같은 열 위치와 간격을 적용하고 마지막 불완전 행은 기존 Incomplete Row Alignment에 따른다. 마지막 행만 전체 폭에 다시 흩뿌려 열 정렬을 깨뜨리지 않는다. 데이터 수가 적다고 사용자가 지정한 최대 열 개념을 임의로 바꾸지 않는다.

### 적은 열·큰 슬롯

최대 열 수를 균형형보다 줄이고 최소·최대 셀 크기를 크게 설정한다. 초기 비교 후보는 최대 3~4열과 셀 72~96 UI 단위이며 실행 화면에서 조정한다. 간격·Padding은 독립적으로 설정하고 부족한 높이는 기존 세로 스크롤로 처리한다. 빈 슬롯까지 포함한 표시 수를 유지한다.

### 수동 및 유효성

기존 FixedColumns·AdaptiveCellSize·ExactColumns와 수동 설정 결과를 유지한다. 특히 ExactColumns는 폭이 부족하다고 다른 모드로 자동 변경하지 않는다. 기존 부족 공간 정책과 진단을 보존한다.

0·음수·NaN·Infinity, 최소값이 최대값보다 큰 범위와 비정상 열 수는 안전하게 정규화한다. Viewport가 아직 0인 초기 프레임에서는 최종 설정을 확정하지 말고 기존 초기 레이아웃 준비 흐름을 따른다. 셀 1개조차 들어가지 않는 극단적인 폭에서는 겹침·무한 계산 없이 공간 부족을 진단한다. 지원하는 최소 화면에서는 실제로 접근 가능하도록 부모 영역과 최소 크기를 검증한다.

최종 셀 크기와 간격을 Content 높이·Navigation·스크롤·마지막 행 계산에 동일하게 사용한다. 스크롤바 표시로 폭이 바뀌어도 열 수가 계속 왕복하거나 레이아웃이 재귀 갱신되지 않게 한다. 매 프레임 전체 재구축·검색·할당을 하지 않고 크기·설정·표시 수가 바뀔 때 갱신한다.

## 6. 데이터·공유 화면·입력 보존

- Actions의 기존 PreserveSlots와 플레이어 퀵 슬롯 번호를 유지한다. 열 수를 바꾸면서 항목을 정렬하거나 빈 슬롯을 제거하지 않는다. 슬롯 수와 등록 상태는 UI 밀도 조정 수단이 아니다.
- 선택한 항목·슬롯과 포커스를 가능한 한 유지하고 현재 열 수에 맞춰 상하좌우 Navigation을 재계산한다. 수량 갱신마다 불필요하게 스크롤을 초기화하지 않는다.
- Icon·EmptySlot의 기존 비율·상한 정책, 수량·단축키·쿨다운·선택 프레임이 새 크기에서도 읽히는지 확인한다. 공유 ActionGridCell.prefab의 크기 정책을 일괄 변경하여 Bag 외형까지 바꾸지 않는다. 필요한 Actions 전용 외형 조정은 명시적 인스턴스 설정이나 필요한 최소 범위로 한정한다.
- 마우스·터치·키보드·컨트롤러의 기존 Input System과 명령 실행 경로를 유지한다. 아이콘 크기와 클릭 영역을 혼동하지 않으며 슬롯 사이 입력 영역이 겹치지 않게 한다.
- 새 기본값은 Actions 인스턴스에만 저장한다. Bag·데모·다른 화면은 명시적으로 새 방식을 선택하지 않는 한 이전 계산과 값을 유지한다. 플레이어 데이터·세이브·인벤토리 정책은 변경하지 않는다.

## 7. 실제 적용 순서

1. AppScene에서 운영 화면으로 진입하여 Actions의 실제 Viewport, Canvas Scaler, 셀 수·크기·간격·그림 크기·부모 배정 높이와 스크롤바 점유를 기록한다. Bag 내부 Grid와 운영 Actions를 참조 관계로 구분한다.
2. 현재 화면과 균형형 후보를 같은 해상도·슬롯 수에서 비교한다. 부모가 공간을 부족하게 배정했는지도 확인하되 주변 패널 전체 재설계는 하지 않는다.
3. 네 선택지와 설정 우선순위를 구현하고 기존 수동 모드의 결과를 검증한다.
4. Unity 연결·컴파일·Play Mode·미저장 상태를 확인한 뒤 TMP_MainScene의 Actions에만 균형형을 적용한다. Prefab 전체 재생성이나 무관한 Scene 저장은 하지 않는다.
5. Bag의 기본 표시가 유지되는지, 개발자가 의도적으로 전환하면 실제 설정 원본을 통해 반영되는지 검증한다. 공유 생성기의 기본값을 변경하여 모든 화면이 새 외형으로 바뀌지 않게 한다.
6. 자산 재로드와 Play 재실행 후 적용값을 확인한다. 최종 수치를 기록하고 전후 화면을 남긴다.

자동화가 불가능하면 원인·완료한 작업·남은 적용과 검증을 보고한다. 필요한 경우에만 Actions 표시 설정을 선별 적용하는 임시 메뉴를 제공한다. 메뉴의 정확한 경로·저장·반복 실행·덮어쓰기 범위를 문서화하고 도구 제공만으로 적용 완료라고 보고하지 않는다.

## 8. 검증 기준

- 네 방식 전환과 수동값 복원, 비활성 상태 변경 후 재활성화, 저장·재로드·실행 후 설정 유지, Bag의 외부 ConfigureLayout 호출과 충돌 여부를 확인한다.
- 표시 수 0·1·C-1·C·C+1, 여러 행과 마지막 불완전 행, 빈 슬롯 포함 상태를 검증한다. 셀 순서·슬롯 ID·용량·등록이 바뀌면 안 된다.
- 공간 배분의 1열, 최소·최대 간격, 폭 부족, 초광폭과 스크롤바 폭 변화를 검사한다. 최종 셀·간격·Content 높이와 Navigation이 일치해야 한다.
- 휴대폰 세로·가로, 태블릿, 일반 데스크톱·울트라와이드, 좁은 Viewport·safe area·방향 변경에서 간격과 식별성을 확인한다. 각 화면의 해상도·Canvas Scale·열 수·셀 크기·실제 간격을 기록한다.
- 셀 그림뿐 아니라 수량·단축키·쿨다운·포커스 프레임의 겹침과 잘림을 확인한다. 터치·마우스·게임패드·키보드, 컨텍스트 메뉴 위치·복귀, 선택 셀 자동 스크롤을 확인한다.
- 같은 해상도의 변경 전후 화면으로 밀집감 개선을 평가한다. 수치만 바꿨다고 적절한 표시가 검증된 것으로 보고하지 않는다. 실제 기기와 Editor 시뮬레이션은 구분한다.
- ActionGridPanelTests와 관련 셀 크기·초기 스크롤 테스트를 수행하고 새 간격 계산·모드 전환·호환성의 집중 테스트를 추가한다. 무관한 테스트 확장은 하지 않는다.
- 가능한 빌드 대상에서 컴파일을 확인하고 실제 기기·빌드·입력 중 미검증 항목과 이유를 보고한다. 성능은 측정 없이 보장하지 않는다. 직렬화 diff에서 Bag·메뉴·플레이어 데이터의 의도하지 않은 변경을 확인한다.
