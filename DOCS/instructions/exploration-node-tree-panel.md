# 탐험 노드 기록 트리 패널 구현

## 1. 목적과 확정 범위

플레이어에게 제시된 탐험 후보와 실제 진행 경로를 기존 NodeTreePanel 영역에 트리로 표시한다. 기본 연결선은 실선이며, 개발자가 노드 이미지·연결선 이미지를 바꾸고 이후 효과를 추가할 수 있는 표시 구조를 제공한다. 이 문서는 후속 구현 지침이며 현재 트리 UI가 구현·적용되었다는 기록이 아니다.

사용자가 확정한 방향은 다음과 같다.

- 진행 방향은 위에서 아래이며 같은 단계의 후보는 가로로 나란히 배치한다. 과거 기록은 세로 스크롤로 탐색한다.
- 선택한 노드와 함께 당시 선택지에 있던 미선택 후보, 현재 선택 가능한 후보를 표시한다. 아직 생성되지 않은 미래 후보는 표시하지 않는다.
- 이번 트리는 경로와 상태를 보여주는 읽기 전용 UI이다. 노드 클릭으로 상세 창을 열거나 진행·되돌아가기를 실행하지 않는다. 실제 노드 선택은 기존 카드에서 수행한다.
- 사용자 지정 대상은 TMP_MainScene의 `Canvas/Main_FlexibleLayoutPanel/NodeTreePanel`이다. 필요하면 `ExplorationNodeTreePanel`로 이름을 바꿀 수 있다.
- 노드와 선에는 향후 효과를 적용할 수 있게 한다. 이번 필수 범위는 정적 표시, 이미지 교체와 효과 적용 경계이며 새 화려한 애니메이션·효과 편집기·셰이더 시스템은 요구하지 않는다.

현재 탐험 데이터는 세션 메모리에 보관된다. 디스크 저장·이어하기, 전체 미래 맵 생성, 새로운 노드 게임 규칙·보상, 기존 후보 카드 대체, 트리 직접 선택 기능은 범위 밖이다.

## 2. 선행 조사와 현재 사실

`AGENTS.md`, `DOCS/README.md`, `DOCS/architecture/exploration-node-tree.md`, `DOCS/architecture/flexible-layout-panel.md`, `DOCS/architecture/project-structure.md`, `DOCS/development/workflows.md`를 읽는다. Git 상태와 기존 변경을 보존한다. `.codegraph/`가 있으면 호출·영향 분석에 먼저 사용하고 실제 소스·자산으로 확인한다. 임의로 재색인하지 않는다.

작성 시 확인한 구조는 다음과 같다.

- `ExplorationRunState.Nodes`에는 가상 Root와 생성된 모든 후보가 있다. `ExplorationNodeRecord`는 Id, ParentId, ChoiceSetId, SiblingIndex, Depth, TypeId, Status, CompletionReason을 보유한다.
- `Select`는 선택 노드를 Active, 같은 후보 집합의 나머지를 Unchosen으로 바꾸고 SelectedPath에 선택 ID를 추가한다. `CompleteActive`가 완료 노드를 부모로 다음 후보를 생성한다. 미선택 노드 아래에는 다음 단계가 생성되지 않는다.
- 상태는 Available, Active, Unchosen, Completed, Failed이다. 가상 Root의 Depth는 -1이며 첫 후보의 부모이다.
- `PlayerSessionHost`가 임시 탐험을 보유하고 `ExplorationRunController`가 Scene 초기화·선택·완료·실패·전투 연결을 담당한다. Scene 재바인딩은 기존 탐험을 재사용한다.
- 도메인 코드에는 현재 트리 전용 변경 이벤트가 없다. UI가 매 프레임 전체 Nodes를 다시 열거하도록 구현하지 말고 명시적인 갱신 경계를 추가한다.
- 저장된 Scene·Prefab·소스 검색에서는 NodeTreePanel을 확인하지 못했다. 위 Hierarchy 경로는 사용자가 알려준 위치이며 디스크에서 검증된 경로가 아니다. 구현 시 열린 TMP_MainScene에서 실제 대상과 미저장 상태를 먼저 확인한다. 찾지 못하면 중복 패널을 임의 생성하지 말고 정확한 누락을 보고한다.

## 3. 트리 데이터와 연결 규칙

노드의 정체성은 `(RunId, NodeId)`, 연결선의 정체성은 같은 RunId의 `(ParentId, NodeId)`로 관리한다. 이름·타입·목록 인덱스가 같아도 서로 다른 노드를 합치지 않는다. 표시 순서는 Depth와 SiblingIndex를 기준으로 안정적으로 정하고 Dictionary 열거 순서에 의존하지 않는다.

각 노드는 자신의 ParentId에 해당하는 부모에만 연결한다. 동일 단계의 후보 사이를 진행 순서처럼 연결하거나, 모든 이전 단계 노드와 모든 다음 단계 노드를 연결하지 않는다. SelectedPath만 사용하면 미선택 후보가 사라지므로 전체 Nodes로 표시 모델을 만들고 SelectedPath는 실제 경로 상태 확인에 사용한다.

예시 구조는 다음과 같다. A2와 B1을 선택했다면 다음 단계의 부모는 각각 A2, B1이다.

```text
시작
├─ A1 미선택
├─ A2 완료
│  ├─ B1 완료
│  │  ├─ C1 현재 후보
│  │  ├─ C2 현재 후보
│  │  └─ C3 현재 후보
│  ├─ B2 미선택
│  └─ B3 미선택
└─ A3 미선택
```

위 텍스트는 연결 관계 예시이며 실제 화면에서는 A1·A2·A3을 같은 가로 행에 배치한다. 가상 Root는 작은 시작 표식으로 표시하여 첫 후보의 출발점을 설명하되 방문한 게임 노드 수에는 포함하지 않는다. 미선택 후보의 부모선도 실선으로 표시하고, 실제 선택 경로의 선은 두께·표식 등으로 구분한다. 미선택 후보는 선택 가능한 버튼처럼 보이지 않아야 한다.

| 도메인 상태 | 표시 의미 |
| --- | --- |
| Available | 현재 제시된 후보이며 아직 확정되지 않았다. |
| Active | 선택하여 진행 중인 현재 노드이다. |
| Completed | 방문하여 완료한 노드이다. |
| Failed | 방문했지만 실패한 노드이다. |
| Unchosen | 당시 후보였으나 선택하지 않은 노드이다. |

현재 후보와 포커스·호버는 구분한다. 카드 위에 마우스를 올리거나 방향 입력으로 포커스만 이동한 것을 실제 방문 경로로 기록하지 않는다. 기존 선택 검증과 확정 연출 뒤 도메인 상태 변경이 성공한 시점부터 트리에 반영한다.

잘못된 ParentId·중복 ID·순환·알 수 없는 TypeId를 방어한다. 무한 순회하지 않고 진단 가능한 상태로 처리한다. 누락된 부모를 임의로 다른 노드에 연결하지 않는다. 알 수 없는 타입은 기본 아이콘·안전한 이름으로 보여주고 탐험 진행을 막지 않는다.

## 4. 표시·배치·탐색

같은 Depth의 후보를 SiblingIndex 순서대로 한 행에 배치하고, 각 행은 실제 콘텐츠 영역에서 중앙 정렬한다. 선택 후 이전 노드를 중앙으로 재배치하여 전체 과거 트리가 흔들리는 방식은 피한다. 행·노드 크기와 가로·세로 간격·Padding은 개발자가 조절할 수 있어야 한다. 노드·라인은 동일한 Content 좌표계를 사용한다.

긴 기록은 세로로 확장하고 모든 생성 기록에 스크롤로 접근할 수 있게 한다. 폭이 부족한 경우 글자·터치 영역을 무조건 축소하거나 같은 Depth를 여러 단계처럼 줄바꿈하지 않는다. 기본 후보 수에서는 좁은 화면에도 읽을 수 있도록 크기·간격을 조정하고, 설정상 한 행이 들어가지 않는 경우에는 같은 Content의 제한된 가로 이동으로 접근하도록 한다. 전체 화면의 임의 줌·핀치 시스템은 이번에 추가하지 않는다.

최초 바인딩 시 현재 진행 노드 또는 현재 후보 행을 보여준다. 새 단계가 추가될 때 사용자가 최신 구간을 보고 있다면 최신 구간을 따라가되, 과거 기록을 수동 탐색 중이면 강제로 스크롤하지 않는다. 같은 노드의 상태만 바뀌거나 이미지가 늦게 로드되는 경우에도 스크롤 위치를 유지한다. 사용자가 최신 위치로 복귀할 수 있는 명시적인 탐색 수단을 제공한다.

읽기 전용은 스크롤까지 조작 불가라는 뜻이 아니다. 마우스 휠·드래그와 터치 드래그를 지원하고, 키보드·컨트롤러에도 패널 탐색 진입·스크롤·복귀 경로를 제공한다. 트리 표시 갱신이 카드의 초기 무선택 정책이나 현재 모달 포커스를 빼앗지 않게 한다. 장식 노드·선은 불필요한 Raycast를 차단하지 않으며, 노드 클릭으로 게임 명령을 실행하지 않는다.

부모 FlexibleLayout이 정한 패널 위치·크기·형제 순서와 사용자 여백을 보존한다. safe area·방향 변경·화면 비율 변경 시 트리 내부만 재배치하고 노드 간 선을 갱신한다. 긴 이름·한글·크기 확장과 현재 상태를 읽을 수 있어야 하며 상태를 색상만으로 구분하지 않는다.

## 5. 선·노드 이미지와 효과 확장

### 권장 책임 분리

| 구성 | 책임 |

| 트리 패널 View | 스크롤·레이아웃·노드 및 선 View 재사용을 관리한다. |

| 노드 View | 타입 아이콘·이름·상태 표식과 외형·효과용 하위 계층을 소유한다. |
| 연결선 View | 계산된 두 끝점 사이의 실선 또는 Sprite 표현과 효과 계층을 소유한다. |
| 표시 설정 | 타입별 이미지, 상태 스타일, 선 너비·색상·Sprite와 간격 설정을 소유한다. |

이는 책임 구분이며 각 행마다 불필요한 인터페이스·Manager를 만들라는 요구가 아니다. UI가 새 탐험을 생성하거나 도메인 상태를 직접 변경하지 않는다.

### 노드

개발자가 TypeId에 따라 Sprite를 지정할 수 있는 명시적 매핑과 기본 대체 아이콘을 제공한다. 동일 타입의 노드에 같은 이미지를 사용할 수 있으나 상태·ID는 별개이다. 실제 임시 아이콘을 기본으로 연결하여 빈 사각형만 나오지 않게 한다. 이미지 교체는 Inspector 또는 표시 설정 자산에서 가능해야 한다.

레이아웃이 소유하는 NodeRoot와 이미지·효과용 VisualRoot 또는 MotionRoot를 분리한다. 이름·상태 배지·선 연결점도 역할을 명확히 한다. 기본 정적 외형만으로 현재·완료·실패·미선택을 구분할 수 있게 한다. 추후 Animator·Tween·Material 효과가 들어와도 슬롯 좌표나 트리 관계를 덮어쓰지 않게 한다.

### 연결선

기본은 두 연결점 사이를 잇는 연속된 실선이며 Canvas UI 단위의 두께·색상을 설정할 수 있어야 한다. 선은 노드 뒤에 그리며 노드의 부모 방향 연결점에서 자식 방향 연결점까지 이어져 아이콘과 이름을 가리지 않게 한다. UI 마스크·Canvas Scale과 호환되는 Image 또는 UI Graphic 방식을 우선 검토한다.

개발자가 연결선에 임의 Sprite를 지정할 수 있는 실제 설정 경로를 제공한다. Sprite 미지정 시 기본 실선으로 안전하게 동작한다. 이미지의 진행 축·회전·길이·두께·늘이기 방식을 문서화하고, 반복 이미지 표현을 지원한다면 Tiled 설정과 Sprite 임포트 조건을 명시한다. 이미지 비율과 선의 연결 길이는 다른 개념이므로 무조건 Preserve Aspect를 적용하여 선 끝이 노드에 닿지 않는 결과를 만들지 않는다.

선의 기하 계층과 VisualRoot·EffectOverlay를 분리한다. 향후 색상 맥동·발광·흐르는 텍스처 등을 붙일 수 있게 하되 이번에 모두 구현하지 않는다. 기본 선 끝점은 배치용 안정적인 연결점에 고정하고 노드 이미지의 장식 확대만으로 선이 매 프레임 흔들리지 않게 한다. 연결점 자체를 움직이는 효과를 추후 도입할 때에는 해당 끝점 변경을 명시적으로 알리는 경계를 둔다.

공유 Material·설정 자산을 런타임에 수정하지 않는다. 효과를 제거·중지하거나 View를 재사용할 때 색상·알파·배율·회전·구독을 복원한다. 노드·선 교체로 이전 효과 콜백이 다른 ID의 View에 적용되지 않아야 한다. 기존 효과 끄기·움직임 줄이기 옵션을 우회하지 않으며 이번 기본 동작에는 지속 애니메이션을 요구하지 않는다.

## 6. 상태 갱신과 수명

최초 세션 바인딩, 선택 성공, 노드 완료와 새 후보 생성, 전투 패배·지원하지 않는 처리기 실패, Scene 재진입, 새 탐험 교체를 모두 갱신 지점으로 다룬다. 현재 Controller의 전투 선택 경로는 ShowChoices를 다시 호출하지 않으므로 후보 표시 함수에만 갱신을 붙여 Active 상태가 누락되지 않게 한다.

완료와 후보 생성은 하나의 일관된 스냅샷으로 반영하여 잠깐 부모만 보이거나 중복 선이 생기지 않게 한다. 도메인에 작은 변경 알림을 추가하거나 Application의 상태 변경 경계를 통합하는 방법 중 현재 규모에 맞는 방식을 선택한다. 전역 Update 폴링과 여러 호출자가 임의로 View를 수정하는 경로는 피한다.

RunId가 바뀌면 이전 노드·선·비동기 이미지 결과를 정리한다. 동일 RunId·NodeId 갱신은 기존 View를 재사용하며 중복 생성하지 않는다. Scene 재바인딩 때 탐험을 새로 추첨하거나 과거 경로를 재실행하지 않는다. 패널 숨김·파괴에서 이벤트와 이미지 자산 수명을 정리한다. 트리 표시 오류가 기존 노드 선택·전투 진행을 막지 않도록 표시 실패를 분리하고 안전한 안내와 진단을 남긴다.

현재 최대 탐험 깊이는 제한되어 있지 않다. 기록 데이터를 삭제해서 UI 부하를 줄이지 않는다. 우선 노드 ID 기반 재사용·변경 시 레이아웃과 화면 밖 효과 중지를 적용하고, 100·500단계 정도의 합성 데이터로 노드·선 수, 갱신 시간·할당을 측정한다. 필요하면 화면 밖 View를 가상화하되 기록 손실·스크롤 범위 축소 없이 구현한다. 측정 없이 모바일 성능을 보장하지 않는다.

## 7. 대상 오브젝트와 실제 적용

먼저 열린 TMP_MainScene에서 사용자 지정 `Canvas/Main_FlexibleLayoutPanel/NodeTreePanel`을 확인한다. 미저장 오브젝트일 수 있으므로 디스크 Scene을 다시 열어 사용자 작업을 잃지 않게 한다. 발견한 계층·현재 구성·부모 레이아웃 참조를 기록한다. 대상이 없으면 다른 패널을 추측하여 교체하지 말고 위치 확인이 필요함을 보고한다.

실제 역할이 트리 표시 전용임을 확인하면 해당 오브젝트 이름을 ExplorationNodeTreePanel로 바꿀 수 있다. 문자열 경로·Editor 도구·테스트·직렬화 참조를 먼저 조사하고 이름 변경에 영향을 받는 연결을 갱신한다. 런타임 연결에는 이름 검색 대신 명시적 참조를 사용한다.

패널의 기존 배치·FlexibleLayoutItem·배경·효과 레이어와 사용자 편집을 보존하면서 내부 Viewport·Content·EdgesLayer·NodesLayer를 구성한다. 카드 선택 패널이 전투 동안 비활성화되어도 기록 트리는 지정된 독립 영역에서 유지되어야 한다. 원본 패널 전체를 임의 생성 Prefab으로 교체하지 않는다.

재사용 노드·선 Prefab은 필수 내부 참조를 완성하여 저장한다. 새 Prefab 생성기를 만들 필요가 있을 때만 저장소의 등록·검증 규칙을 따른다. 이번 통합에 영구 Tools 메뉴를 반드시 만들 필요는 없다. Unity 연결·컴파일·Play Mode·미저장 변경을 확인한 뒤 필요한 자산과 Scene 연결을 선별 적용하고 저장 후 재로드하여 검증한다. 무관한 미저장 변경을 묵시적으로 저장하지 않는다.

## 8. 검증과 완료 기준

- 처음 생성된 후보, 한 번 선택, 여러 단계 진행, 미선택 형제, 완료·Active·Failed, 현재 Available을 검증한다. 각 edge가 원본 ParentId와 정확히 일치하고 미선택 후보 아래에 가짜 미래가 없어야 한다.
- 동일 타입 반복, 후보 수 1·3·다수, 신규 RunId, 중복 갱신, Scene 재진입, 미등록 타입·누락 부모·잘못된 순환 입력을 검사한다. 표시 오류로 도메인이 바뀌지 않아야 한다.
- 노드 카드의 포커스·호버·확정 대기 동안에는 방문 경로를 바꾸지 않고 실제 선택 성공 후 상태가 반영되는지 확인한다. 전투 중 트리 유지와 패배·완료 즉시 갱신을 포함한다.
- 실제 노드·선 Sprite를 교체하고 저장·재실행 후 유지되는지 검사한다. 선 Sprite 제거 시 실선 대체, 비정사각형 노드 이미지, 긴 선·짧은 선과 Canvas Scale 변화에서 연결점을 확인한다.
- 효과용 루트에 일시적인 색상·알파·배율 변화를 적용하여 Layout 위치와 ID·선 연결이 유지되는지 검증한다. 재사용·Disable 후 원복을 확인하고 시험용 효과를 운영 기본값에 남기지 않는다.
- 마우스·터치·키보드·컨트롤러 탐색과 최신 위치 복귀를 확인한다. 과거 스크롤 중 갱신으로 강제 이동하거나 카드·모달의 포커스를 빼앗지 않아야 한다.
- 데스크톱·울트라와이드·휴대폰·태블릿, safe area·방향 변경·한글과 긴 문구를 확인한다. 좁은 영역에서도 노드·상태·선과 전체 기록에 접근할 수 있어야 한다.
- 도메인 기존 테스트, 순수 표시 투영·배치 Edit Mode 테스트, 실제 바인딩·상태 갱신·Scene 수명 Play Mode 검증을 수행한다. 합성 긴 기록은 테스트/데모 세션에만 만들고 실제 플레이어 데이터에 넣지 않는다.
- AppScene에서 실제 운영 Scene으로 진입한 스크린샷과 적용 경로를 남긴다. 실제 기기·Editor 시뮬레이션·빌드·성능 중 수행한 것만 보고하고 직렬화 diff의 무관한 변경을 확인한다.

## 9. 문서와 최종 보고

구현 후 `DOCS/architecture/exploration-node-tree.md`의 미구현 트리 설명을 실제 범위에 맞게 수정한다. 새 표시 책임·계층·스냅샷·연결점·효과 수명을 설명할 필요가 있으면 architecture 아래 별도 문서를 추가하고 색인에 연결한다. `DOCS/architecture/project-structure.md`에는 신규 View·연결자·자산 경계를, `DOCS/development/workflows.md`에는 이미지·선 Sprite 교체 위치, 임포트 조건·패널 연결·검증 절차를 기록한다.

최종 보고에는 확인한 실제 대상 경로와 이름 변경, 데이터·연결 규칙, 적용한 노드·선 기본 자산, 개발자 설정·효과 확장 위치, 실제 Scene 적용·검증과 미검증 항목을 구분한다. 자동화가 막히면 구체적인 원인과 남은 작업을 보고하고 코드·도구만으로 완료 처리하지 않는다. 사용자가 실행할 Tools 단계가 남으면 별도 `사용자가 수행할 적용 절차`에 정확한 메뉴 경로·전제·순서·저장·반복 실행·오류 중단·최종 검증을 fenced text 블록으로 제공하고 개발 문서에도 남긴다. 남은 수동 Tools 단계가 없으면 없다고 명시한다.
