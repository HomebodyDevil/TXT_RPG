# 런타임 설정 가능한 주사위 도메인 구현

## 목적과 확정된 방향

장기 유지보수를 고려한 텍스트 RPG의 주사위 객체를 구현한다. 사용자가 확인한 방향은 다음과 같다.

- 각 면에 정수 하나를 지정한다. 같은 숫자를 여러 면에 지정할 수 있다.
- 모든 면은 동일한 확률로 선택한다. 숫자의 종류가 아니라 면을 추첨한다.
- 개발자가 허용 최솟값·최댓값을 설정한다. 소수는 지원하지 않는다.
- 이번에는 생성, 런타임 면 구성 변경, 굴림과 테스트까지 구현한다.
- 플레이어 소유, 임의 개수 장착, 저장·복원과 메인 게임 루프 연결은 추후 구현한다. 이번에 운영 상태나 저장 포맷을 변경하지 않는다.

이 문서는 구현 예정 지침이며 제안된 클래스는 현재 구현된 타입이라고 가정하지 않는다. 새롭게 결과에 중요한 모호성이 발견되면 AGENTS.md에 따라 방향을 확인한다.

## 최소 구조와 책임

기존 프로젝트 관례를 우선하며 아래 역할을 구현한다. 역할마다 반드시 별도 파일이나 인터페이스가 필요한 것은 아니다.

| 제안 역할 | 책임 |
| --- | --- |
| `Dice` | 독립적인 면 구성을 소유하고 검증된 변경 및 굴림 진입점을 제공한다. |
| 면 구성과 값 범위 | 순서가 있는 정수 목록과 허용 범위를 나타낸다. 외부에서 직접 변경할 수 없는 형태로 노출한다. |
| 난수 공급자 | 유효한 면 인덱스를 균등하게 생성한다. 테스트에서 대체 가능하게 주입한다. |
| `DiceRollResult` | 선택된 면 인덱스와 당시 숫자를 불변 값으로 보존한다. |

MonoBehaviour, GameObject, UI, 물리 시뮬레이션, Scene 검색이나 전역 매니저 없이 굴릴 수 있어야 한다. 결과는 직접 반환하며 현재 필요하지 않은 이벤트 버스나 비동기 계층을 추가하지 않는다. ScriptableObject 저작 도구, 이미지, 3D 모델, 굴림 애니메이션, 전용 Scene 및 Tools 메뉴는 이번 범위에 포함하지 않는다. 향후 외형은 논리 결과를 표현하는 계층으로 연결한다.

## 면과 숫자 계약

- 면 수의 단일 원본은 면 값 목록의 길이다. 별도의 면 수 필드와 값 목록이 서로 불일치하는 상태를 허용하지 않는다.
- 4면, 6면, 8면 등을 구성할 수 있어야 한다. 기하학적으로 가능한 다면체 목록으로 제한하지 않는다. 여기서 면 수는 논리적인 결과 칸의 수다.
- `[1, 1, 3, 5]`는 4면이며 서로 다른 숫자는 3개다. 1의 확률은 2/4, 3과 5는 각각 1/4이다. 중복을 제거하지 않는다.
- null 또는 비어 있는 면 목록으로 유효한 주사위를 만들지 않는다. 허용 범위는 양 끝을 포함하고 최솟값이 최댓값보다 크면 거부한다. 음수와 0도 설정한 범위 안이면 허용한다.
- 기본 허용 범위는 암묵적으로 게임 규칙에 고정하지 말고 생성 시 명시적으로 전달할 수 있게 한다. 예제의 D6는 값 `[1,2,3,4,5,6]`과 범위 `[1,6]`을 사용하며 운영 기본 주사위로 지급하지 않는다.
- 입력 배열·리스트는 복사하여 소유한다. 호출자가 원본을 수정하거나 반환된 컬렉션을 변형해 주사위 검증을 우회할 수 없어야 한다. 같은 원본으로 만든 두 주사위가 런타임 변경 상태를 공유하지 않아야 한다.

## 런타임 변경

전체 면 구성 교체를 제공하여 면 수와 각 숫자를 함께 변경할 수 있게 한다. 특정 면 값 변경도 명확한 API로 제공한다. API 이름은 기존 프로젝트 관례에 맞춰 결정한다.

허용 범위도 바꿀 수 있어야 하며 면 목록과 범위를 함께 검증·교체하는 경로를 제공한다. 범위를 좁혀 기존 면 값이 범위 밖이 되는 경우에는 변경을 거부한다. 숫자를 자동 Clamp하거나 면을 삭제하여 확률을 몰래 바꾸지 않는다.

변경은 먼저 전체 검증한 후 한 번에 반영한다. 실패하면 기존 구성은 그대로 유지되어야 한다. 잘못된 인덱스와 범위 밖 숫자의 오류 방식은 기존 도메인의 예외 또는 결과 타입 관례에 맞추고 테스트한다. 검증 실패 로그만 출력하고 성공처럼 진행하지 않는다.

기본적으로 같은 실행 흐름에서 사용하는 동기 객체로 설계한다. 스레드 안전성을 보장하지 않는다면 명시하고 불필요한 잠금 구조는 추가하지 않는다. 굴림 중 사용하는 면 구성과 결과 값은 일관된 상태여야 한다.

## 굴림과 난수

굴림은 `[0, FaceCount)` 범위의 인덱스를 한 번 선택하고 해당 값을 결과에 기록한다. 숫자의 최솟값~최댓값을 직접 추첨하거나 중복을 제거한 값 목록을 추첨하지 않는다.

기존 난수 공급자가 적합하면 재사용한다. 없다면 최소한의 주입 경계와 실제 런타임에서 사용할 수 있는 균등 정수 공급 구현을 제공한다. 매 굴림마다 시간 기반 시드로 새 난수기를 만들지 않는다. 전역 Unity Random 상태에 주사위 규칙을 숨기지 않는다. modulo 편향을 만드는 수동 변환 대신 지원되는 균등 정수 API를 사용한다.

테스트에서는 지정한 인덱스를 반환하는 공급자로 결과를 정확하게 검증한다. 같은 시드의 결과가 플랫폼·런타임 버전까지 영구적으로 일치한다고 보장하지 않는다. 저장 가능한 RNG 상태, 리플레이 프로토콜, 보안 추첨·네트워크 권위 검증은 이번 범위가 아니다.

결과에는 0부터 시작하는 면 인덱스와 당시 값을 담는다. UI에 표시할 면 번호는 표현 계층에서 변환한다. 굴린 뒤 주사위 구성을 바꾸어도 이전 결과 값은 바뀌지 않아야 한다. 난수 공급자의 잘못된 인덱스를 조용히 보정하거나 다시 추첨하지 말고 계약 위반으로 처리한다.

## 추후 소유·장착·게임 루프 연결

같은 종류의 주사위라도 면 구성이 달라질 수 있으므로, 향후 공용 콘텐츠 정의와 플레이어가 소유한 개별 인스턴스를 구분할 수 있도록 설계한다. 이번에는 소유 ID 체계나 저장 스키마를 미리 확정하지 않는다.

장착 개수·슬롯 제한·중복 장착·정렬 순서·아이템 스택 정책은 추후 별도 요구로 결정한다. 주사위 클래스 안에 플레이어 검색, 장착 여부 확인이나 단일 전역 주사위 제한을 넣지 않는다.

여러 독립 주사위를 생성하고 각각 굴릴 수 있어야 한다. 결과 합산, 최댓값 선택, 재굴림, 턴 진행 등은 미래 게임 루프 책임이며 이번에 임의 확정하지 않는다. 향후 저장에는 면 구성과 범위 등 필요한 값 데이터를 기록하는 경로를 사용할 수 있게 하되 현재 PlayerState·인벤토리·저장 파일은 변경하지 않는다.

## 검증 기준

1. 4/6/8면 생성과 FaceCount, 면별 숫자를 검증한다.
2. `[1,1,3,5]`의 각 인덱스를 가짜 난수로 선택하여 중복 면이 독립적으로 유지되는지 검증한다. 작은 표본의 빈도 테스트를 필수 통과 기준으로 삼지 않는다.
3. 난수 요청 범위가 정확히 `[0, FaceCount)`인지, 첫·마지막 면이 선택되는지 확인한다. 실제 난수 구현이 지정된 범위를 지키는지도 확인한다.
4. 면 값 변경, 4→8면 전체 교체, 범위 변경 후 다음 굴림에 반영되는지 검증한다.
5. null·빈 목록, 뒤집힌 범위, 범위 밖 숫자, 잘못된 인덱스·난수 응답을 확인하고 실패 후 기존 상태가 유지되는지 검증한다.
6. 음수·0·동일 숫자 면·범위 경계값을 확인한다. 정수 경계값 처리에서 불필요한 덧셈·범위 계산 오버플로가 없어야 한다.
7. 입력 컬렉션 변경, 두 인스턴스 중 하나의 변경, 굴림 후 구성 변경이 다른 인스턴스와 이전 결과에 영향을 주지 않아야 한다.
8. 여러 주사위의 생성·개별 굴림을 테스트하고 결과를 합산하는 게임 규칙은 추가하지 않는다.
9. 영향 어셈블리 컴파일, 신규 테스트와 관련 기존 Gameplay 테스트를 수행한다. 테스트 통과와 실제 기기 검증을 구분한다. UI 변경이 없으므로 불필요한 Scene 연출 검증은 추가하지 않는다.
