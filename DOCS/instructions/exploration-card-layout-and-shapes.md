# 탐험 선택 카드 정렬·간격·도형 구현 지침서

## 목적과 확정 사항

기존 탐험 선택 카드의 배치와 외형을 개발자가 설정할 수 있도록 확장한다. 이 문서는 구현할 요구사항이며, 아래의 현재 상태와 구분한다. 장기 유지보수가 필요한 소규모 게임에 맞게 기존 구성요소를 확장하고 범용 UI 프레임워크를 새로 만들지 않는다.

- 가로 정렬은 좌측·중앙·우측, 세로 정렬은 상단·중앙·하단을 제공한다.
- 세로형 카드를 가로로 배치하고, 너비가 부족하면 줄바꿈하는 기존 방향을 유지한다.
- 목록의 상하좌우 Padding과 카드 사이의 가로·세로 간격을 제공한다. 개별 카드 Margin은 이번에 구현하지 않는다.
- 이미지 기반 외형을 유지하면서 사각형·둥근 사각형·원형·타원형·삼각형을 수학적으로 생성하는 모드를 추가한다. 크기와 적용 가능한 모서리 곡률을 설정할 수 있어야 한다.
- 도형은 배경·테두리와 이미지에 적용한다. 텍스트는 도형으로 잘리지 않는 별도 영역에 표시하고 클릭 영역은 사각형으로 유지한다.
- 개별 변 길이와 꼭짓점별 곡률 편집은 추후 확장 사항이다. 이번에는 공통 곡률을 제공한다.
- 실제 회전 애니메이션, 노이즈·모자이크 효과, 임의 다각형 편집기, 새로운 탐험 규칙은 구현 범위가 아니다.

## 책임과 데이터 소유권

| 구성 | 책임 |
| --- | --- |
| 기존 LayoutGroup | 직사각형 카드 점유 영역, 줄바꿈, 정렬, 간격, 목록 Padding을 계산한다. |
| 기존 CardList | 목록 갱신, 재사용, Viewport 높이 반영, 포커스와 스크롤을 조정한다. |
| 기존 CardView | 표시 데이터와 선택 요청을 연결하고 재사용 시 외형 상태를 초기화한다. |
| 도형 설정 | 표시 방식, 도형 종류, 도형 영역 크기, 공통 곡률, 색상·테두리 설정을 보유한다. |
| 도형 표시 컴포넌트 | 도형 계산·배경·테두리·이미지 마스킹을 처리한다. 탐험 도메인에 의존하지 않는다. |

새 클래스 이름과 파일은 기존 UI 관례에 맞춰 최소한으로 정한다. 도형 설정은 직렬화 가능한 값 객체로 시작하고, 공유 프리셋이 실제로 필요하면 ScriptableObject로 분리한다. 공유 자산은 런타임 변경의 저장소로 사용하지 않는다. 인스턴스별 변경은 복사한 설정 또는 명시적 override로 관리한다. 전역 매니저나 Scene 검색으로 연결하지 않는다.

Scene 초기화는 기존 Controller → CardList → CardView 경로를 유지한다. Prefab 내부 필수 참조는 저장된 자산에서 완성한다. Run ID·Choice Set ID·Node ID에 기반한 선택 검증을 유지한다.

## 배치 요구사항

### 정렬과 줄바꿈

1. 기존 LayoutGroup의 `childAlignment`를 활용하거나 동일 의미의 단일 설정으로 통합한다. 동작하지 않는 상속 설정과 별도 설정을 중복 노출하지 않는다.
2. 가로 정렬은 각 행의 실제 카드 묶음에 적용한다. 마지막 행에 카드가 적어도 해당 행을 좌측·중앙·우측으로 정렬한다. 우측 정렬을 선택해도 데이터 순서와 행 안의 좌→우 순서는 뒤집지 않는다.
3. 세로 정렬은 모든 행을 포함한 묶음 전체에 적용한다. 남는 높이가 있을 때 상단·중앙·하단을 선택할 수 있어야 한다.
4. 콘텐츠가 Viewport보다 크면 상단 기준으로 배치하고 세로 스크롤로 모든 행에 접근하게 한다. 중앙 정렬 때문에 맨 위 행이 음수 영역으로 잘려서는 안 된다.
5. 콘텐츠 높이가 내용 높이와 정확히 같으면 세로 정렬 차이가 보이지 않는다. 이를 해결하기 위해 목록의 유효 Content 높이는 최소한 Viewport 높이를 확보하고, 넘칠 때만 내용 높이로 확장한다. ContentSizeFitter와 LayoutGroup이 같은 축의 크기를 서로 덮어쓰거나 반복 갱신하지 않도록 크기 결정 책임을 한 곳에 둔다.
6. 이전 기본값인 가로 중앙·세로 상단, 카드 210×300, 간격 18×18을 호환 기본값으로 유지한다. 설정값은 Inspector와 런타임 변경 API 양쪽에서 반영되어야 한다.

### 계산 기준과 여백

- Padding은 목록 경계에서 카드 묶음까지의 안쪽 여백이다. 가로·세로 Spacing은 인접 카드 또는 행 사이에만 적용한다. 마지막 카드·마지막 행 뒤에 추가하지 않는다.
- 카드 내부의 이미지·텍스트 여백은 별도 콘텐츠 inset이다. 목록 Padding과 혼용하거나 중복 차감하지 않는다.
- 사용 가능 너비는 실제 Content/Viewport 관계와 활성 스크롤바 정책을 반영하고, Padding을 한 번만 차감한다.
- 행 높이 합계에 Padding과 행 사이 간격을 더해 필요 높이를 계산한다. 남는 너비·높이에 정렬 계수 0, 0.5, 1을 적용한다. 넘침에는 음수 정렬 여백을 적용하지 않는다.
- 카드보다 좁은 화면에서는 최소 한 열을 유지한다. 지원 최소 해상도에서 카드 전체가 접근 가능한지 검증하고 기존 크기 유지 정책과 충돌하는 미지원 너비는 명확히 보고한다. 임의로 카드 축소나 가로 스크롤 정책을 바꾸지 않는다.
- 비활성 카드와 ignoreLayout 자식은 Unity 레이아웃 관례대로 제외한다. 카드가 0개일 때도 잘못된 높이, NaN, 불필요한 스크롤이 없어야 한다.
- 정렬과 크기 변경으로 탐험 후보를 재생성하지 않는다. 새 후보를 표시할 때는 기존 맨 위 시작 정책을 유지하되, 단순 해상도 변경에는 매번 맨 위로 강제 이동하지 않는다.

## 도형과 표현 계층

기존 구조를 보존하면서 다음 책임 경계를 갖도록 필요한 부분만 수정한다.

```text
CardRoot                  사각형 배치·Button·입력 영역
└─ MotionRoot             향후 이동·회전·확대 연출
   └─ VisualRoot
      ├─ ShapeVisual      도형 배경·도형으로 잘리는 이미지·테두리
      ├─ TextContent      제목·설명·상태, 도형 마스크 밖
      ├─ FocusVisual      키보드·컨트롤러 포커스
      └─ EffectOverlay    향후 효과 영역
```

### 설정과 기하 조건

- 표시 방식은 기존 이미지 기반 방식과 절차적 도형 방식으로 구분한다. 별도 텍스처 없이도 도형 배경과 테두리가 보여야 한다. 이미지가 있으면 같은 도형 안으로 잘라 표시하고, 없으면 배경·텍스트만으로 사용 가능해야 한다.
- 카드의 Layout 크기와 ShapeVisual의 크기는 분리한다. 원형이나 삼각형으로 바꾸어도 카드의 직사각형 점유 영역과 텍스트 영역이 임의로 바뀌지 않는다. 이번에는 목록 안 카드들의 Layout 크기를 공통으로 유지한다.
- ShapeVisual은 자신의 할당 영역 안에서 크기를 설정한다. 원형은 가로·세로 중 작은 길이를 지름으로 사용해 비율을 유지한다. 타원형은 독립적인 가로·세로 크기를 사용한다. 삼각형은 위를 향한 이등변삼각형을 기본으로 하고 폭·높이로 형태를 조절한다.
- 둥근 사각형과 삼각형에는 공통 모서리 반경을 적용할 수 있게 한다. 0이면 각진 형태다. 사각형과 원형·타원형에 의미 없는 반경 설정은 비활성화하거나 설명한다.
- 반경은 도형이 자기 교차하거나 변이 뒤집히지 않는 범위로 제한한다. 삼각형은 짧은 변과 각도를 고려한 유효 최대 반경을 계산한다. 단순히 사각형과 같은 제한식을 재사용하지 않는다.
- 테두리는 도형 내부에 그려 점유 영역을 늘리지 않는다. 과도한 두께는 유효 범위로 제한한다. 잘못된 크기, 음수, NaN, Infinity에는 안전한 대체값을 적용한다.
- 개별 변·꼭짓점 편집을 위한 사용하지 않는 배열과 범용 편집기는 만들지 않는다. 새 도형 계산기를 추가할 때 CardList나 탐험 도메인을 변경하지 않는 책임 경계를 유지한다.

### 구현 방식과 효과 호환

- 현재 UGUI·마스킹·렌더 파이프라인·플랫폼 요구를 조사하고, 지원 가능한 최소 방식으로 구현한다. 권장 출발점은 도형 경계 계산을 공유하는 커스텀 MaskableGraphic과 필요한 이미지 마스크 조합이다. 별도 고급 셰이더 프레임워크를 전제로 하지 않는다.
- 배경, 테두리, 이미지 마스크가 동일한 도형 정의를 사용하여 경계가 어긋나지 않아야 한다. 이미지 종횡비 정책을 명시하고 찌그러뜨리지 않는다. 기존 이미지 표현 정책이 있으면 우선 유지한다.
- 외부 ScrollRect의 RectMask2D와 내부 도형 마스크의 중첩을 실제로 확인한다. 텍스트는 내부 도형 마스크의 자식으로 두지 않되 외부 Viewport 마스크는 적용되어야 한다.
- 장식 Graphic은 Raycast를 차단하지 않는다. 도형 밖이더라도 CardRoot의 사각형 안은 클릭 가능하다. 포커스 표시는 원형·삼각형에서 사라지지 않아야 한다.
- 재질 공유로 다른 카드에 효과나 색 변경이 전파되지 않도록 한다. 생성한 Mesh·Material 등 자원의 소유자와 해제 시점을 명확히 하고, 재사용·비활성화·Scene 종료에서 누수와 잔상이 없어야 한다.
- 곡선 분할 수는 제한하고 설정·크기가 변경된 경우에만 기하를 갱신한다. 매 프레임 재생성, 레이아웃 재진입, 불필요한 GC 할당을 피한다. 모바일 성능은 실제 측정 없이 보장하지 않는다.
- 이번에는 실제 애니메이션이나 노이즈·모자이크 효과를 추가하지 않는다. 향후 효과가 MotionRoot, ShapeVisual, 텍스트 등 필요한 대상에 적용될 수 있도록 참조와 책임만 분리한다.

## Inspector·호환성·적용

- 정렬, 카드 크기, 간격, 목록 Padding, 도형 모드와 도형 매개변수를 명확한 그룹과 Tooltip으로 설명한다. 개별 카드 Margin은 제공하지 않는다고 문서화한다.
- Editor에서 설정 변경 결과를 확인할 수 있어야 한다. OnValidate는 값 정규화와 안전한 갱신 예약에 한정하고 자산 전체 재생성을 연결하지 않는다.
- 기존 직렬화 필드와 Prefab override를 보존한다. 필드명을 바꾸면 필요한 마이그레이션을 제공한다. 기본 설정 누락으로 카드가 보이지 않아서는 안 된다.
- TMP_MainScene과 관련 카드 Prefab에 실제로 적용한다. 기존 장면 구성, 탐험 상태, 저장 데이터, 다른 Panel의 배치를 변경하지 않는다. 기본 외형은 호환되게 유지하며 각 도형은 격리된 Preview 또는 테스트 구성으로 검증한다.
- 생성기 관리 자산인지 개발자 편집 자산인지 확인하고 원본 정책을 지킨다. 전체 Prefab 재생성을 기본 적용 방법으로 삼지 않는다. 임시 적용 메뉴가 필요한 경우 AGENTS.md의 수동 적용 안내 규칙을 따른다.

## 검증 기준

1. 정렬 9개 조합을 높이 여유가 있는 영역에서 확인한다. 카드 1·2·3개와 여러 행, 마지막 행이 덜 찬 경우를 포함한다.
2. 비대칭 Padding, 간격 0과 큰 값, 0개·비활성 카드, 정확히 한 열이 더 들어가는 경계 너비를 테스트한다. 계산 테스트는 예상 좌표·필요 높이를 검증한다.
3. 높이가 부족하면 처음 표시할 때 맨 위 행부터 보이고 마지막 행까지 스크롤된다. 넘침이 사라지면 선택한 세로 정렬이 적용된다. 설정·해상도 변경 시 반복 레이아웃이나 스크롤 점프가 없어야 한다.
4. 다섯 도형, 곡률 0·유효 최대·초과 입력, 매우 좁거나 작은 도형, 두꺼운 테두리, 이미지 유무를 확인한다. 원이 타원이 되거나 삼각형 경계가 자기 교차하지 않아야 한다.
5. 이미지가 도형 바깥으로 새지 않고 텍스트는 잘리지 않는다. 외부 Viewport 밖의 모든 카드 표시 요소는 정상적으로 잘린다. 직사각형 클릭 영역과 실제 포커스 동작을 확인한다.
6. 마우스·터치·키보드·컨트롤러, 좁은 화면·넓은 화면·높은 배율·긴 한국어 텍스트를 검증한다. 동일 카드의 반복 Bind/Unbind와 런타임 스타일 전환에서 상태가 섞이지 않아야 한다.
7. 기존 탐험 선택, 중복 클릭 방지, 이전 후보 요청 거부, 전투 완료 후 새 후보 표시를 회귀 검증한다.
8. 관련 Edit Mode 테스트와 Play Mode 확인을 수행한다. 실행하지 못한 항목은 미검증으로 보고한다. Console 예외·경고와 실제 적용 화면을 확인한다.
