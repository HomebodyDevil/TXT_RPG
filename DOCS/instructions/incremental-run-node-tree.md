# 점진 생성 노드 트리와 탐험 진행 시스템

## 목적과 확정 사항

플레이어가 무작위 노드 선택지 중 하나를 선택하고 완료한 뒤 다음 선택지를 받는 탐험 흐름을 구현한다. 선택·미선택 노드를 모두 구조화된 트리로 기록한다. 이번 작업은 시스템·최소 선택 UI·기존 전투 연결까지 포함하며 전체 트리를 그리는 시각화는 추후 작업이다.

사용자가 확인한 규칙은 다음과 같다.

- 되돌아가기는 없다. 미선택 노드는 기록만 남기고 방문할 수 없다.
- 선택한 노드를 완료했을 때만 그 아래에 다음 선택지를 생성한다. 미래 트리를 미리 생성하지 않는다.
- 탐험 동안 체력과 진행 트리를 유지한다. 앱 재실행 저장·이어하기는 이번에 구현하지 않는다.
- 기본 선택지는 3개다. 전투와 회복·강화 종류를 각각 50% 확률로 독립 선택하므로 같은 종류가 중복될 수 있다. 개수와 종류별 가중치는 개발자가 설정할 수 있게 한다.
- 회복·강화 노드는 이번에 효과를 구현하지 않는다. 선택 후 `회복 및 강화: 미구현` 안내와 `계속` 버튼을 표시한다. 계속을 누르면 효과 없이 완료하고 다음 선택지로 진행한다.

새로운 결과 영향 규칙은 임의로 확정하지 않는다. 탐험 최대 깊이·엔딩·보상·난이도 성장·상점·강화 효과·정식 저장은 이번 범위가 아니다.

## 최소 책임 구조

신규 Gameplay/Runtime/Exploration 및 Application/Runtime/Exploration 경로는 제안이며 기존 적합한 구조가 있으면 재사용한다.

| 역할 | 책임 |
| --- | --- |
| 탐험 상태 | 탐험 ID, 현재 노드, 선택지 집합, 트리 기록, 진행 단계와 탐험 플레이어 상태를 소유한다. |
| 노드 생성기 | 설정과 전용 난수 공급자로 요청받은 단계의 선택지만 생성한다. |
| 진행 조율자 | 선택·진입·완료·실패를 검증하고 다음 단계로 전환한다. |
| 노드 처리기 | 전투 또는 미구현 회복·강화의 시작·종료 계약을 구현한다. |
| 표현 연결 | 선택 UI, Story, 적·체력·행동 버튼을 현재 상태에 바인딩한다. |

역할마다 전역 Singleton이나 Manager를 만들지 않는다. Gameplay는 Unity UI·Scene 이름에 의존하지 않고, Application이 기존 세션과 화면을 연결한다. 향후 노드 종류는 안정적인 Type ID와 명시적인 처리기 등록으로 확장할 수 있게 한다. 거대한 switch를 여러 UI와 시스템에 복제하거나 임의 reflection으로 타입을 검색하지 않는다.

## 트리 모델과 기록

처음 선택 전에는 실제 플레이 노드가 없으므로 가상의 Root를 기록 구조의 부모로 사용한다. Root는 전투나 이벤트로 실행하지 않는다. 최초 후보 3개를 Root의 자식으로 저장하고 하나를 선택하면 그 노드가 최초 Entry가 된다.

각 노드에 안정적인 Node ID, Parent ID, 형제 표시 순서, 깊이, Type ID, 생성 당시 콘텐츠 설정 스냅샷 또는 불변 참조, 방문·결과 상태를 기록한다. 후보 집합에도 식별자를 부여하여 오래된 UI 요청을 거부할 수 있게 한다. Node ID와 종류 ID를 혼동하지 않는다.

후보 상태는 Available → Active/Unchosen, 방문한 노드는 Active → Completed/Failed처럼 명시적으로 전환한다. 선택 순간 형제의 미선택 상태를 확정하며 그 노드들은 자식 없이 기록에 남긴다. 미선택을 실패나 완료로 취급하지 않는다. 효과 없는 회복·강화 완료에는 `PlaceholderAcknowledged` 같은 이유를 남겨 실제 효과 수행과 구분한다.

트리는 문자열 로그가 아닌 데이터로 보존한다. 부모 연결과 정렬 순서로 나중에 UI가 전체 선택 구조를 복원할 수 있어야 한다. 탐험 경로는 선택된 연결을 따라 조회 가능해야 한다. 현재 위치와 마지막 완료 노드, 현재 후보 집합을 분리해 선택 대기 중 위치가 모호하지 않게 한다.

외부에 변경 가능한 내부 컬렉션을 그대로 노출하지 않는다. 완료된 기록을 이후 ScriptableObject 수정 때문에 다른 내용으로 바꾸지 않는다. 이번에는 파일 저장을 하지 않지만 Unity 객체 참조만으로 기록을 구성하지 않는다.

## 생성과 상태 전환

```text
새 탐험 생성 → 최초 선택지 생성·기록 → 선택 대기
→ 하나 선택·형제 미선택 확정 → 해당 노드 진행
→ 성공 완료 → 다음 선택지 생성·기록 → 선택 대기
→ 전투 패배 시 탐험 실패 종료
```

후보는 화면을 열거나 다시 바인딩할 때 재생성하지 않는다. 같은 선택 집합에서 누르지 않은 사이 내용이 바뀌지 않아야 한다. 생성과 기록 반영을 하나의 일관된 처리로 구성하여 중복 자식이 생기지 않게 한다.

노드 생성 난수와 주사위 굴림 난수는 별도 공급 흐름으로 분리한다. 테스트에서 지정 결과를 주입할 수 있게 한다. 50% 기본은 각 후보별 동일 종류 확률을 뜻하며 두 종류가 반드시 포함된다는 보장은 없다. 가중치 음수·전체 0·미등록 종류·선택지 수 0 등 잘못된 설정은 명확히 거부한다. 유효 콘텐츠가 없을 때 무한 재추첨하거나 가짜 기본 노드를 만들지 않는다.

완료 처리는 활성 Node ID와 요청의 식별 정보를 검증한다. 중복 승리 이벤트·계속 연타·과거 UI의 선택 요청으로 노드가 두 번 완료되거나 선택지가 다시 생성되지 않아야 한다. 미완료 노드에서 다른 후보로 이동하지 못하게 한다. 선택지 생성 실패는 복구 가능한 오류 상태로 남기고 완료한 전투를 다시 실행하지 않는다.

## 탐험 수명과 전투 연결

새 탐험을 처음 시작할 때 운영 캐릭터 상태에서 독립적인 탐험 상태를 한 번 만든다. 노드마다 운영 체력을 다시 복사하지 않는다. 탐험 체력은 전투 후 다음 노드까지 이어지며 운영 저장 상태로 역반영하지 않는다. Scene 재바인딩은 기존 탐험 상태를 표시하고 새 탐험을 몰래 생성하지 않는다.

기존 임시 적은 Scene 진입 즉시 나타나는 대신 전투 노드를 선택해 진입할 때 생성한다. 기존 임시 전투 설정의 적·공격/회복 교대·주사위 순서 규칙을 유지한다. 적 처치가 전투 노드 완료 신호이고 패배는 탐험 실패다. 완료 신호는 전투 결과 전체 처리가 끝난 뒤 한 번 전달하여 남은 회복 효과와 충돌하지 않게 한다.

가능하면 탐험 HealthState를 전투에 명시적으로 연결하여 단일 원본으로 사용한다. 복사·동기화가 필요하다면 적용 시점과 중복 방지를 테스트한다. UI가 운영·전투·탐험 상태 중 두 곳에서 동시에 체력을 받지 않도록 한다.

선택 대기와 회복·강화 노드에서는 전투 행동을 실행하지 않는다. 미구현 노드는 안내·계속만 제공하며 HP·스탯·주사위를 수정하지 않는다. 향후 강화 상태를 탐험에 둘 수 있는 경계만 확보하고 이번에 빈 강화 프레임워크를 만들지 않는다.

앱 재실행 시 이전 탐험은 복원하지 않는다. 종료된 탐험 기록은 세션 내에서 조회 가능하게 유지한다. 새 탐험/캐릭터 교체/기존 아이템 사용이 탐험에 미치는 규칙이 필요한 경우 추가 확인하고 운영 상태와 임시 탐험 상태를 암묵적으로 섞지 않는다.

## 최소 UI와 확장

TMP_MainScene에서 최초 후보 3개를 선택 가능한 버튼 또는 카드로 보여준다. 기존 Modal 경로를 쓴다면 지정된 Window 서비스로 열고, 직접 패널을 쓴다면 기존 배치에 최소한으로 연결한다. 기본 시각 설계를 전면 변경하지 않는다.

종류와 미구현 여부를 텍스트로 명확히 표시한다. 선택 후 후보 UI를 닫거나 입력을 막고 해당 노드 내용을 보여준다. 미구현 노드에는 `회복 및 강화: 미구현. 이번에는 효과가 적용되지 않습니다.`와 계속 버튼을 제공한다. 다음 후보 표시 시 초기 포커스를 설정하고 키보드·컨트롤러·터치로 선택할 수 있게 한다.

StoryTextPanel에는 선택·진입·완료·실패를 실제 상태에 맞춰 추가하고 기존 전투 결과 로그를 유지한다. UI를 다시 열었다는 이유로 기록 메시지를 중복 추가하지 않는다. 트리 시각화는 만들지 않되 테스트나 읽기 전용 진단으로 미선택 형제와 부모 연결을 확인할 수 있게 한다.

## 검증 기준

1. 최초에는 Root와 후보 3개만 있고 미래 자식은 없어야 한다.
2. 하나 선택 시 위치·Active·미선택 형제 2개가 정확히 기록되고 이전 후보는 다시 선택할 수 없어야 한다.
3. 전투 승리 또는 미구현 계속 처리 후 선택 노드 아래에만 후보 3개가 한 번 생성되어야 한다. 미선택 노드에는 자식을 생성하지 않는다.
4. 노드 3회 이상 진행하여 부모 연결·형제 순서·깊이·선택 경로와 미선택 이력이 보존되는지 확인한다.
5. 전투 피해가 다음 노드로 이어지고 미구현 노드에서 체력·강화가 변하지 않아야 한다. 운영 PlayerState와 저장 파일에는 탐험 변경을 반영하지 않는다.
6. 중복 완료·선택 연타·오래된 요청·미등록 처리기·잘못된 생성 설정·초기화 실패를 검사한다. 일부 실패로 이미 완료된 효과를 반복하지 않는다.
7. 가짜 난수로 같은 종류 후보 3개도 정상인지 확인한다. 작은 표본의 빈도 테스트를 통과 조건으로 삼지 않는다.
8. 화면 재활성화·콘텐츠 Scene 재연결에서 후보 재추첨·체력 초기화·적 중복 생성·구독 누수가 없어야 한다.
9. 전투 패배 후 이동과 행동이 차단되고 트리 실패 기록이 유지되어야 한다.
10. 관련 Gameplay/Application 자동 테스트, 컴파일과 실제 TMP_MainScene 선택→전투→다음 선택 흐름을 검증한다. 미구현 안내·계속 및 한국어·좁은 화면·지원 입력을 확인하고 수행하지 못한 항목을 보고한다.
