# GameMenuPanel 버튼 확장 및 반응형 배치 작업 지침

## 1. 목적과 작업 범위

현재 TMP_MainScene에 개발자가 배치한 GameMenuPanel을 유지하면서, 버튼의 기능과 외형을 독립적으로 확장하고 배치 방식을 Inspector와 런타임 API에서 선택할 수 있도록 구현합니다. 이 문서의 신규 형식과 API 이름은 설계 제안이며, 이미 구현된 기능을 의미하지 않습니다.

- 포함: 버튼 View 분리, 수평 스크롤, 반응형 줄바꿈, 크기·간격·패딩·정렬 설정, 입력과 포커스, 기존 자산 마이그레이션, 테스트와 문서 갱신입니다.
- 제외: 가방·스탯·옵션의 게임 규칙 변경, 새로운 창 시스템, 실제 노이즈·모자이크 셰이더 제작, Addressables 구조 개편, 다른 패널의 전면 리팩터링입니다.
- 새 Scene은 만들지 않습니다. 기존 메뉴의 위치, 부모, 형제 순서, FlexibleLayoutItem 설정과 창 연결을 보존합니다.

- DOCS/development/workflows.md

프리팹의 GameMenuPanel 직렬화에는 m_Script가 0이고 클래스 식별자가 기재되어 있습니다. 실제 컴포넌트가 정상적으로 로드되는지 Editor에서 확인합니다. Missing Script가 확인되면 관련 컴포넌트만 안전하게 복구하고, 다른 창 클래스 전체를 임의로 이동하지 않습니다. 클래스 파일을 분리해야 한다면 참조 보존과 마이그레이션을 검증합니다.

현재 작업 트리에는 기존 변경과 미추적 자산이 있습니다. 이를 사용자 작업으로 취급하고, 일괄 생성기가 Scene이나 다른 자산을 덮어쓰는지 먼저 확인합니다.

## 3. 배치 옵션: 두 모드와 열 정책

권장 구성은 LayoutMode = HorizontalScroll / Wrap입니다. 신규 기본값은 HorizontalScroll로 하여 현재 한 줄 배치를 유지하면서 좁은 폭에서도 버튼에 접근할 수 있게 합니다.

| 설정 | 의미 |
| --- | --- |
| ButtonSize | 공통 버튼 너비와 높이입니다. Canvas 기준 UI 단위를 사용합니다. |
| Spacing | 수평·수직 버튼 간격입니다. 수평 모드에서는 X만 사용합니다. |
| Padding | 버튼 배치 영역의 Left, Right, Top, Bottom 여백입니다. |
| HorizontalAlignment | Left, Center, Right입니다. Wrap에서는 각 행에 적용합니다. |
| VerticalAlignment | 여유 높이가 있을 때 Top, Center, Bottom을 선택합니다. |
| WrapColumnPolicy | AutoFit 또는 MaximumColumns를 선택합니다. |
| MaximumColumns | 폭에 들어가는 열 수의 상한입니다. 정확한 고정 열 수가 아닙니다. |

크기는 양수이고, 간격과 패딩은 0 이상이어야 합니다. MaximumColumns는 1 이상이어야 합니다. 잘못된 직렬화 값과 런타임 입력을 검증하고 보정 또는 거부 정책을 일관되게 적용합니다.

Inspector에는 해당 모드에 유효한 설정만 표시하거나 비활성화합니다. 실제 열 수·행 수·필요 높이·공간 부족 여부를 읽기 전용으로 확인할 수 있게 합니다. OnValidate에서는 가벼운 검증과 갱신 예약만 수행하고, 객체를 반복 생성하거나 Scene을 저장하지 않습니다.

### 3.1 HorizontalScroll

- 한 줄을 유지하고 버튼을 축소하거나 줄바꿈하지 않습니다.
- ScrollRect는 horizontal=true, vertical=false로 구성하고 Viewport에서 클리핑합니다.
- 콘텐츠가 들어가면 스크롤을 정지하고 지정한 수평 정렬을 적용합니다. 넘치면 최초 위치는 왼쪽이며, 양 끝 버튼과 설정한 패딩에 모두 접근할 수 있어야 합니다.
- 버튼 수 N에 대한 콘텐츠 너비는 좌우 패딩 합 + N×버튼 너비 + max(0, N-1)×수평 간격으로 계산합니다.
- 수평 스크롤바는 선택 기능으로 두고 Visibility = Hidden / Auto / Always를 지원합니다. Hidden은 핸들만 숨기며 드래그와 포커스 이동은 유지합니다.
- 스크롤바를 제공한다면 하단에 배치하고 핸들·배경 Image를 명시적으로 참조합니다. Auto는 넘칠 때만 표시합니다. 숨겼을 때 스크롤바 높이를 예약할지는 명시적으로 설정하며, 좌우 여백을 추가하지 않습니다.
- 스크롤바 핸들은 일반적인 콘텐츠 비율 크기를 사용합니다. ActionGridPanel의 별도 핸들 정책을 무조건 복사하지 않습니다.
- 단일 버튼보다 Viewport가 좁아도 가로 이동으로 양쪽을 볼 수 있어야 하며, 터치 가능한 최소 크기를 검증합니다.

### 3.2 Wrap

가용 너비 W는 Viewport 너비에서 좌우 패딩을 뺀 값입니다. 버튼 너비 B, 수평 간격 S에 대해 다음을 사용합니다.

- fitColumns = floor((W + S) / (B + S))입니다.
- AutoFit의 열 수는 fitColumns이며, MaximumColumns는 min(fitColumns, 설정 상한)입니다.
- 표시 항목이 있을 때 계산 열 수는 최소 1로 처리하되 W < B는 별도의 공간 부족 상태로 보고합니다.
- 행 수는 ceil(표시 버튼 수 / 실제 열 수)입니다.
- 필요 높이는 상하 패딩 합 + 행 수×버튼 높이 + max(0, 행 수-1)×수직 간격입니다.
- 버튼이 없을 때 행 수는 0이며, 필요한 높이는 패딩 합입니다.

버튼 목록의 순서는 항상 왼쪽에서 오른쪽, 위에서 아래로 유지합니다. Right 정렬은 버튼 순서를 뒤집는 옵션이 아닙니다. 비활성 상태이지만 보이는 버튼은 자리를 유지하고, 숨겨진 버튼은 계산에서 제외합니다.

각 행의 실제 버튼 수로 행 너비를 계산합니다. 남는 너비의 0%, 50%, 100%를 시작점에 더하여 Left, Center, Right를 구현합니다. 마지막 행도 같은 규칙을 적용합니다. 예를 들어 3열에 5개 버튼이 있으면 첫 행은 A B C, 두 번째 행은 D E 순서이며 두 번째 행 자체를 정렬합니다.

이 모드에서는 수평·수직 스크롤을 모두 끕니다. 고정 열 수를 억지로 유지하여 폭 밖으로 밀어내거나, 남는 공간을 채우려고 버튼을 늘리지 않습니다.

### 3.3 부모 높이와 전체 표시 보장

고정 버튼 크기, 제한된 폭과 높이, 모든 버튼 표시를 항상 동시에 만족시킬 수는 없습니다. 다음 계약을 구현합니다.

- 메뉴는 Unity 레이아웃 계약에 맞는 preferredHeight와 최소 필요 너비를 제공합니다.
- 부모가 이를 소비하는지 실제 FlexibleContentLayoutGroup 코드를 확인합니다. ILayoutElement를 구현하는 것만으로 부모가 높이를 반영한다고 가정하지 않습니다.
- 루트 크기는 부모가 소유하고 메뉴는 내부 버튼 배치만 소유합니다. 동일 RectTransform에 부모 레이아웃과 ContentSizeFitter를 경쟁시키지 않습니다.
- 부모가 고정 높이를 사용하는 경우 필요한 높이를 Inspector에 표시하고 개발자가 부모 설정을 조절할 수 있게 합니다. 자동 높이 연계가 필요하면 메뉴에 한정된 명시적 어댑터를 검토하고, 모든 FlexibleLayoutItem의 동작은 바꾸지 않습니다.
- 폭 또는 높이가 부족하면 LayoutInsufficientSpace 상태와 중복 억제 경고를 제공합니다. Wrap을 몰래 스크롤 모드로 바꾸거나 버튼을 축소하지 않습니다. 부족 상태에서는 Viewport 경계로 잘라 주변 UI를 침범하지 않게 하며, 이 상태를 전체 표시 성공으로 판정하지 않습니다.
- TMP_MainScene에서는 기존 위치와 다른 요소를 보존하면서 필요한 공간을 확보합니다. 기존 배분을 변경하지 않고는 불가능하다면 임의 재배치하지 말고 필요한 최소 크기와 선택지를 보고합니다.

## 4. 버튼의 기능과 시각 요소 분리

최소한 다음 책임을 분리합니다. 신규 클래스명은 예시이며, 기존 관례에 맞춰 확정합니다.

| 요소 | 책임 |
| --- | --- |
| GameMenuPanel | 표시 항목, 명령 실행 연결, 레이아웃 설정과 포커스 조정을 담당합니다. |
| GameMenuButtonView | Button, 라벨, 아이콘, 배경, 테두리와 표시 상태를 연결합니다. |
| GameMenuLayoutGroup | 버튼의 크기와 위치 및 선호 크기 계산만 담당합니다. |
| 메뉴 항목 데이터 | 안정적인 식별자, 명령 대상, 표시 데이터와 가시성 정보를 표현합니다. |
| 명령 처리 경계 | 실행 가능 여부와 실행 요청을 처리하며, 기존 Open(pageId) 경로를 기본 구현으로 사용합니다. |

- 현재의 pageId, 버튼 참조, visible 및 창 연결을 유지하거나 명시적으로 마이그레이션합니다. 표시 문구나 객체 이름으로 명령을 분기하지 않습니다.
- 새 메뉴를 추가할 때 레이아웃 코드를 수정할 필요가 없어야 합니다. 범용 명령 프레임워크를 새로 만들지는 않습니다.
- 메뉴 항목 정의와 런타임 표시 상태를 분리합니다. 재사용 수요가 있다면 ScriptableObject 설정을 사용하되 모든 버튼에 별도 자산을 강제하지 않습니다.
- ButtonRoot는 레이아웃과 입력 영역을 담당하고, 자식 VisualRoot에 Background, Icon, Label, Border, EffectOverlay를 둡니다. 별도 버튼 프리팹을 재사용할 수 있게 합니다.
- 애니메이션은 VisualRoot나 개별 Graphic에 적용하며 ButtonRoot의 배치 크기를 흔들지 않습니다.
- 기본/선택/포커스/눌림/비활성/실행 중 상태를 표현할 수 있게 합니다. Unity Button 전환과 추가 효과가 같은 속성을 동시에 덮어쓰지 않게 책임을 나눕니다.
- 외형은 런타임에 교체할 수 있게 하며, 공유 Material이나 ScriptableObject를 직접 변경하지 않습니다. 생성한 Material, 효과, 비동기 로드의 소유자와 해제 시점을 명확히 합니다.
- 장식 Graphic은 raycastTarget을 끄고, Viewport 밖 효과의 클리핑 정책을 문서화합니다.
- 긴 번역 문구의 줄바꿈·말줄임 정책과 전체 이름에 접근할 대안을 제공합니다. 글자가 길다는 이유로 버튼 배치 크기를 변경하지 않습니다.
- 이벤트는 한 번만 구독하고 해제합니다. 중복 Button 바인딩은 검증하며 RemoveAllListeners로 개발자의 기존 이벤트를 삭제하지 않습니다.
- 서비스 또는 대상 페이지가 없으면 실행 불가 상태와 진단을 제공하며, 예외로 패널 전체를 중단하지 않습니다.

## 5. 런타임 갱신과 입력

- 모드·크기·간격·패딩·열 정책·정렬을 변경할 API를 제공하고 한 번의 갱신으로 반영할 수 있게 합니다.
- 화면 크기, 회전, Safe Area, 버튼 추가·삭제·숨김 변경 시 다시 계산합니다. 매 프레임 전체 버튼 재생성이나 강제 Canvas 갱신을 하지 않습니다.
- 모드 전환 시 이전 스크롤 속도를 정지하고 오프셋을 유효 범위로 보정합니다. 가능하면 선택한 항목 ID를 보존합니다.
- 마우스, 터치 드래그, 키보드와 게임패드 Navigate/Submit/Cancel을 지원합니다. 드래그 종료를 클릭으로 오인하여 창을 열지 않습니다.
- 수평 휠 입력을 지원하고 일반 세로 휠을 수평 이동으로 변환할지는 설정으로 구분합니다. 중첩 ScrollRect의 입력을 무조건 가로채지 않습니다.
- 선택 버튼이 화면 밖에 있으면 전체 버튼이 보이도록 최소한만 스크롤합니다. 버튼 자체가 Viewport보다 크면 앞쪽 경계를 보여주는 정책을 적용합니다.
- Wrap의 상하 탐색은 인접 행에서 가장 가까운 수평 위치로 이동하고, 숨김·실행 불가 항목을 건너뜁니다. 패널 외부로 이동할 경로와 창 종료 후 포커스 복원을 보존합니다.

## 6. 구현 순서와 호환성

1. 실제 Editor 배치, Prefab override, 창 서비스 연결 및 현재 테스트를 확인합니다.
2. 레이아웃 계산을 테스트 가능한 코드로 분리하고 크기·열·정렬 계산을 먼저 검증합니다.
3. 버튼 View와 두 배치 모드를 구현하며 현재 세 버튼의 명령을 유지합니다.
4. Editor에서 조절 결과를 확인할 수 있게 하되 편집 모드에서 창 열기나 게임 서비스 실행은 금지합니다.
5. 기존 GameMenuPanel 프리팹과 생성기를 함께 갱신합니다. 기존 GUID, 직렬화 참조, 사용자 버튼 이벤트와 Scene override를 보존합니다.
6. TMP_MainScene에 이미 배치한 인스턴스를 대상으로 필요한 변경만 적용합니다. 파괴적 전체 재생성은 사용하지 않습니다.
7. 관련 테스트와 문서를 갱신합니다.

기존 설정을 이전할 때 버튼 크기 150×48, 간격 12, 패딩 12/12/8/8, 중앙 정렬을 보존합니다. 신규 예시는 이 값을 기준으로 작성하되 모든 기존 인스턴스에 강제 덮어쓰지 않습니다.

## 7. 검증 및 완료 기준

- Edit Mode에서 버튼 수 0, 1, 3, 5, 20과 정확한 경계 너비 및 경계 ±1을 테스트합니다.
- 예: 내부 너비 474, 버튼 너비 150, 간격 12이면 3열이며, 473이면 2열입니다.
- 예: 버튼 5개, 3열, 버튼 높이 48, 수직 간격 12, 상하 패딩 8이면 필요 높이는 124입니다.
- Wrap의 AutoFit/MaximumColumns, 마지막 행 좌·중·우 정렬, 숨김과 비활성의 차이, 1개 버튼보다 좁은 폭, 부족한 높이를 검증합니다.
- HorizontalScroll에서 버튼 크기 유지, 양 끝 접근, 맞는 너비에서 정렬, 스크롤바 Hidden/Auto/Always와 불필요한 예약 공간을 검증합니다.
- 런타임 모드 전환, 크기 변경, 목록 변경 후 포커스·속도·레이아웃이 정상인지 확인합니다.
- 여러 번 활성화해도 한 번 클릭에 한 번만 창이 열리는지 확인합니다.
- System/Inventory/Status 창 요청, 빠른 아이템 컨텍스트 메뉴 닫기, 모달 종료 후 포커스 복원을 회귀 검증합니다.
- 좁은 모바일 세로 화면, 가로 화면, 태블릿, 데스크톱과 넓은 화면에서 버튼 겹침·잘림·입력 경합을 확인합니다.
- 실제 테스트 화면의 해상도, 배율, 모드와 사용 설정을 기록하고 스크린샷을 남깁니다. 실제 디바이스 미검증을 Editor 검증과 구분합니다.
- 생성기 재실행으로 같은 메뉴가 재현되는지 격리된 대상으로 확인하고, TMP_MainScene 및 다른 프리팹에 의도하지 않은 변경이 없는지 diff를 검토합니다.
