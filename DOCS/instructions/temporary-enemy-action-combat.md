# 행동 버튼과 임시 적 전투 구현

## 목적과 확정 방향

TMP_MainScene의 기존 주사위 굴림 버튼 표시 이름을 `행동`으로 변경하고, Scene 진입 시 임시 적 1개와 체력 바·다음 행동을 표시한다. 버튼을 누르면 플레이어 주사위 효과를 실제 전투 상태에 적용한 뒤 살아 있는 적이 행동한다.

사용자가 선택한 사항은 다음과 같다.

- 플레이어 주사위 효과 적용 → 살아 있는 적 행동 순서다.
- 플레이어 공격은 임시 적, 회복은 전투에 참여한 플레이어 캐릭터를 대상으로 한다.
- 적은 공격·회복을 교대로 수행한다. 체력 바 옆에 다음 행동을 표시하고 실제 수행 결과는 StoryTextPanel에 남긴다.
- 플레이어 스탯을 복사한 임시 전투 상태를 사용한다. 운영 플레이어 상태·저장은 변경하지 않고 Scene 재진입 시 초기화한다.

이 문서는 구현 예정 지침이다. 정식 전투 전체, 장착·보상·경험치·저장·3D 굴림은 범위에서 제외한다. 추가적인 전투 규칙이 필요하고 결과에 중요한 영향을 주면 임의 확정하지 말고 사용자에게 확인한다.

## 최소 구성과 상태 소유권

| 역할 | 책임 |
| --- | --- |
| 임시 전투 설정 | 활성 여부, 적 외형·이름·최대 체력·공격량·회복량을 개발자가 설정한다. |
| 전투 상태 | 플레이어 복사 상태와 적 상태, 진행 상태·현재 턴·다음 적 행동을 소유한다. Unity UI를 참조하지 않는다. |
| 행동 처리 | 주사위 결과를 한 번만 얻어 효과를 적용하고 이후 적의 예고된 행동을 처리한다. |
| 표현 연결 | 적 외형, 양쪽 체력 바, 다음 행동과 Story 기록을 상태에 연결한다. |

기존 HealthState와 피해 해석 경계를 활용한다. UI가 직접 HP를 계산하거나 DamageManager라는 이름으로 같은 계산을 복제하지 않는다. 실제 적용량은 HealthChangeResult를 사용한다. 현재는 면의 공격 수치를 기본 피해로 전달하고 기존 passthrough resolver를 사용한다. 임의 공격력 가산·방어력·치명타 규칙을 추가하지 않는다.

## Scene 진입과 테스트 적

세션·활성 캐릭터가 준비된 후 현재 캐릭터의 최대/현재 체력과 필요한 스탯 값을 독립적인 전투 상태로 복사한다. 원본 HealthState나 변경 가능한 스탯 컬렉션을 공유하지 않는다. 이미 체력이 0이면 숨은 회복으로 전투를 시작하지 않고 시작 불가 상태를 표시한다.

임시 적은 1개로 시작한다. 초기 제안값은 최대/현재 체력 40, 공격 5, 회복 3이며 Inspector에서 변경 가능해야 한다. 사용자가 적절한 수치 설정을 위임했으므로 이 값은 테스트용으로 조정 가능하나 최종 값을 보고한다. 첫 다음 행동은 `공격 5`, 이후 `회복 3`과 교대한다.

기존 EnemyDisplayPanel과 사용 가능한 적 외형을 우선 재사용한다. 모델·이미지가 없으면 적임을 식별할 수 있는 명확한 임시 표현을 사용하고 근거 없는 외부 이미지를 가져오지 않는다. 같은 Scene에 DemoLoader와 새 전투 표시 공급자가 서로 덮어쓰지 않도록 표시 소유자를 하나로 정한다. 해당 테스트 범위의 중복 연결만 수정한다.

Scene에 들어오면 적 외형, 체력 바, `현재 / 최대 HP` 텍스트와 다음 행동이 나타나야 한다. 다음 행동 표시는 확정된 의도이며 실행 직전에 다른 행동으로 바꾸지 않는다. 적이 최대 체력이더라도 회복 차례는 그대로 수행하고 실제 회복량 0을 기록한다.

## 행동 버튼과 한 턴

사용자가 보는 제목만 `행동`으로 변경한다. 내부 명령 ID는 불필요하게 바꾸지 않는다. 이름을 바꾼다면 직렬화 연결과 생성기도 함께 처리한다. 별도의 주사위 버튼을 중복 추가하지 않는다.

처리는 기존 동기 주사위 결과를 사용하되 향후 3D 확정 결과를 받을 수 있도록 결과 선택과 적용을 분리한다. 이번에 물리를 구현하지 않는다.

```text
준비 상태 검사·중복 실행 방지
→ 현재 보유 주사위를 각 1회 굴림
→ 보유 순서대로 플레이어 효과 적용·기록
→ 적이 살아 있으면 예고된 행동 1회 적용·기록
→ 생존 상태 확인·다음 행동 갱신·버튼 상태 갱신
```

각 주사위 결과와 실제 변화는 구분한다. 공격은 적에게, 회복은 플레이어 전투 상태에 적용한다. 결과를 출력하기 위해 다시 굴리지 않는다. 음수 등 실행할 수 없는 효과 수치는 전투 시작/행동 준비 단계에서 진단하며 회복을 피해로 자동 변환하지 않는다.

사망 처리의 세부 규칙, 특히 플레이어 주사위 묶음 중 적 체력이 0이 됐을 때 남은 회복 면까지 처리할지는 구현 전에 확인한다. 공통 안전 조건으로 체력 0인 적은 그 턴에 공격·회복하지 않고, 전투 종료 후 추가 행동은 막는다. 자동 부활·적 재생성·보상 지급은 하지 않는다. 승리/패배 상태와 종료 사실은 UI에 표시한다.

빠른 연타·Submit 중복·이벤트 중복으로 같은 요청이 두 번 적용되지 않아야 한다. 처리 중 예외가 발생하면 실패 상태와 실제 반영 범위를 명확히 하고 자동 재실행하지 않는다. UI 표시 실패를 이유로 이미 적용한 피해를 다시 적용하지 않는다.

## UI·로그·운영 데이터 격리

적 체력 바는 상태 변경 이벤트에 따라 갱신하고 필요 없는 매 프레임 전체 검색을 하지 않는다. 체력 바 옆의 다음 행동도 같은 전투 상태에서 읽는다. 여러 적으로 확장할 때 적별 InstanceId로 연결할 수 있게 하되 이번에는 1개만 구현한다.

플레이어 체력 UI 역시 임시 전투 상태를 보여줘야 한다. 기존 운영 상태 Binder와 동시에 같은 HealthBarPanel을 갱신하지 않도록 명시적으로 바인딩을 교체·해제한다. 전투 외 UI에는 원래 운영 상태가 유지되어야 한다. 인벤토리·퀵 아이템이 운영 체력을 변경하는 경로와 임시 전투가 섞이지 않게 조사하고, 그 상호작용을 이번에 지원해야 한다면 추가 방향을 확인한다. 임의로 모든 메뉴를 비활성화하지 않는다.

StoryTextPanel에는 기존 기록 뒤로 추가한다. 예시는 다음과 같다.

```text
[주사위] D6: 공격 5
[전투] 테스트 적에게 피해 5. 체력 35/40.
[적 행동] 공격 5. 플레이어가 받은 피해 5.
```

회복은 요청량과 실제 회복량을 구분한다. 최대 체력 때문에 3 중 1만 회복했다면 실제 1을 기록한다. 한국어 fallback, 스크롤, 기존 Fade를 유지한다.

Scene 종료 시 전투 상태와 구독을 해제한다. 재진입 시 현재 운영 캐릭터 상태에서 새 복사본과 초기 적을 만든다. 플레이어 세션 주사위 상태의 기존 수명은 바꾸지 않는다. 전투 중 캐릭터 교체의 의미는 추가 확인 전 임의로 정하지 않는다. 운영 저장 DTO·저장 파일은 수정하지 않는다.

## 적용과 검증

1. 미저장 변경·Prefab Override·현재 테스트 데이터를 확인하고 기존 TMP_MainScene 레이아웃을 보존한다. 초기 적 표시 완료와 참조 준비 전에 행동 버튼을 활성화하지 않는다.
2. 실제 AppScene 초기화 경로에서 Scene 진입 시 적 1개·HP 40/40·공격 5 예고·행동 버튼을 확인한다.
3. 가짜 난수로 공격/회복 결과를 고정하여 플레이어 효과 다음 적 행동 순서와 실제 HP를 테스트한다.
4. 적 공격/회복 교대, 최대 체력 회복 0, 과도한 피해, 적 사망 시 행동 생략, 플레이어 패배와 중복 클릭 차단을 검증한다.
5. 체력 바·숫자·예고·Story가 같은 상태를 표현하는지 확인한다. 운영 캐릭터 HP와 저장 데이터가 변하지 않아야 한다.
6. Scene 재진입·재실행·비활성화/재활성화 후 중복 적·중복 구독·잔여 상태가 없어야 한다.
7. 기존 메뉴·주사위·Story 기능과 좁은 화면·마우스·터치·Submit 경로를 지원 범위에서 확인한다. 실제 기기 미검증은 명시한다.
8. 관련 Gameplay/Application/UI 테스트와 컴파일을 수행하고 실제 전투 화면을 캡처한다. 단순 Console 출력만으로 UI 검증을 대신하지 않는다.
