# GameMenuPanel 이미지 메뉴와 카테고리형 가방 창 구현 지침

## 1. 목적과 범위

GameMenuPanel의 메뉴를 이미지 중심으로 표시하고 가방 버튼에서 카테고리별 아이템 그리드를 갖춘 모달 창을 엽니다. 개발자가 수직 스크롤 또는 번호 페이지 방식으로 표시하도록 선택할 수 있게 합니다.

여기서 Modal은 배경 화면의 입력을 제한하는 창이며, Model은 데이터 모델입니다. 가방 데이터 모델은 창과 독립적으로 유지합니다.

이 문서는 구현 계획입니다. 신규 형식명은 제안입니다. 메뉴 외형, 가방 창 구성, 필터·표시 방식, 컨텍스트 명령 연결, 관련 프리팹·테스트·문서를 작업합니다. 장비 시스템, 개별 장비 인스턴스, 무게·가방 용량 규칙, 드래그 앤 드롭, 실제 노이즈 셰이더 제작은 이번 범위에서 제외합니다.

| 요소 | 책임 |
| --- | --- |

| ActionGridPanel 및 기존 명령 인터페이스 | Slot 표시, 선택과 컨텍스트 메뉴를 담당합니다. |
| 아이템 명령 서비스 | 사용·퀵 슬롯 등록 등 게임 상태 변경을 담당합니다. |
| 카테고리·표시 설정 | 카테고리 ID와 순서, 표시 모드, 크기·간격 등 개발자 설정을 보관합니다. |

카테고리마다 InventoryState나 전체 UI를 복제하지 않습니다. 하나의 가방 View를 재사용하여 현재 필터의 결과만 표시합니다. 런타임 상태는 일반 C# 객체로 유지하고 ScriptableObject에는 개발자 작성 설정만 저장합니다.

권장 구성은 기존 모달 내부의 CategoryTabs, ItemGrid, PaginationControls, EmptyState, LoadingState, ErrorState입니다. 컨텍스트 메뉴는 Grid 마스크 밖이면서 모달 입력 영역 안에 있는 Overlay에 표시합니다. 별도 전역 Canvas나 EventSystem을 생성하지 않습니다.

## 4. 이미지 중심 메뉴

- 개발자가 메뉴별 Sprite를 Inspector에서 설정할 수 있게 하고 기존 SetIcon을 통한 런타임 교체도 지원합니다.
- 표시 모드는 ImageOnly와 ImageWithLabel을 제공합니다. 기존 텍스트 설정은 마이그레이션 시 보존합니다.
- 기본 가방 메뉴에 알아볼 수 있는 아이콘을 연결합니다. 프로젝트 내 재사용 가능한 자산을 우선하며, 없다면 저작권이 명확한 임시 자산을 추가하고 교체 경로를 문서화합니다.
- Sprite 비율을 유지하고 아이콘 여백·색상을 조절할 수 있게 합니다. 원본 이미지 크기가 ButtonRoot의 배치 크기를 바꾸지 않도록 합니다.
- 이미지에 의미 있는 글자를 구워 넣지 않습니다. 이미지 전용 모드도 현지화된 메뉴 이름과 선택 시 설명을 제공합니다. 마우스 hover만을 설명 접근 수단으로 사용하지 않습니다.
- 이미지 누락 또는 로드 실패 시 빈 클릭 영역 대신 기본 아이콘 또는 이름을 표시합니다.
- Normal, Selected, Pressed, Disabled 상태를 구분하고 색상만으로 상태를 전달하지 않습니다.
- 애니메이션과 효과는 VisualRoot 또는 개별 Graphic에 적용합니다. 공유 Material 원본을 수정하지 않습니다.
- 직접 Sprite 참조는 기본 경로로 사용할 수 있습니다. Addressables가 필요한 경우 기존 Provider/Lease 경로를 재사용하고 빠른 교체·취소·해제 후 늦은 결과가 현재 메뉴를 덮어쓰지 않게 합니다.

## 5. 카테고리와 번호 페이지를 구분합니다

카테고리 탭은 아이템을 분류하는 필터입니다. 번호 페이지는 해당 필터 결과를 일정 개수씩 나누는 표시 방식입니다. 탭을 바꿔도 소유 데이터가 다른 목록으로 이동하지 않습니다.

- ItemDefinition에 안정적인 categoryId를 추가하거나 별도 분류 설정으로 매핑합니다. 현재 규모에서는 대표 카테고리 1개와 가상 All 필터로 시작합니다.
- 카테고리는 수정 가능한 정의 목록으로 관리합니다. ID, 현지화 이름, 아이콘, 표시 순서를 포함합니다. UI switch에 고정 카테고리를 나열하지 않습니다.
- 임시 기본 탭은 전체, 소비품, 기타로 구성합니다. 새 장비 시스템 없이도 추후 분류를 추가할 수 있어야 합니다.
- 기존 정의처럼 카테고리가 비어 있거나 미등록이면 기타로 표시합니다. 이전 저장 파일을 초기화하지 않습니다.
- 알 수 없는 아이템 정의 ID도 데이터에서 삭제하지 않습니다. 진단용 대체 표시와 실행 불가 상태를 사용합니다.
- All을 제외한 카테고리별 필터는 같은 정의가 중복 표시되지 않게 합니다. 정렬은 설정 순서와 안정적인 ID 등 명확한 규칙으로 결정하며 Dictionary 열거 순서에 의존하지 않습니다.
- 빈 카테고리 탭은 기본적으로 유지하고 빈 목록 안내를 표시합니다. 개발자가 빈 탭 숨김을 선택할 수 있다면 현재 탭 소멸 시 All로 돌아갑니다.
- 탭이 많거나 번역이 길 때 탭 영역만 수평 탐색할 수 있게 합니다. 아래 ItemGrid의 수직 입력과 구분합니다.

## 6. Slot의 의미와 두 표시 모드

현재 인벤토리는 정의 ID별 수량입니다. 기본적으로 아이템 종류별 한 Slot에 수량을 표시합니다. 동일 아이템 20개를 20개의 독립 슬롯으로 확장하지 않습니다.

표시용 빈 Slot과 ItemsPerPage는 실제 인벤토리 용량 제한이 아닙니다. 정렬·필터·페이지 이동 시 저장 상태를 바꾸지 않습니다. 항목 식별에는 전체 목록이나 페이지 인덱스가 아니라 안정적인 아이템 ID를 사용합니다. 향후 개별 장비 Instance ID가 필요해질 경우 별도 도메인 확장으로 처리합니다.

### VerticalScroll

- 필터 결과 전체를 세로로 탐색합니다. 수평 스크롤은 사용하지 않습니다.
- ActionGridPanel의 반응형 열 수, 크기·간격·Padding·정렬 정책을 재사용합니다.
- 처음 열기와 사용자 카테고리 변경 시 첫 행부터 표시합니다. 비동기 아이콘 갱신이나 수량 변경마다 맨 위로 이동하지 않습니다.
- 스크롤바 가시성과 외형 설정은 기존 공통 정책을 따릅니다.
- 초기 구현은 실제 지원할 항목 수를 명시하고 측정합니다. 큰 목록이 필요하면 기존 풀링과 별도로 가상화를 검토하되 성능 근거 없이 이번 작업에 강제 도입하지 않습니다.

### Paged

- ItemsPerPage를 1 이상으로 설정합니다. 현재 필터·정렬 결과를 먼저 확정한 뒤 해당 구간만 표시합니다.
- N개 결과, 페이지당 K개이면 pageCount = max(1, ceil(N/K))입니다. UI 페이지 번호는 1부터 표시하고 내부 인덱스는 0부터 사용합니다.
- 이전·다음과 현재/전체 페이지 표시 및 특정 페이지로 이동할 수 있는 컨트롤을 제공합니다. 많은 페이지 버튼을 한꺼번에 생성하지 않고 제한된 번호 범위 또는 페이지 선택 UI를 사용합니다.
- N=0은 빈 화면 한 페이지로 처리하고 이동 컨트롤을 비활성화합니다.
- 기본 마지막 페이지는 실제 항목만 표시합니다. 개발자가 FillPageWithEmptySlots를 켜면 K칸까지 빈 Slot을 표시하며 빈 칸에는 아이템 명령을 제공하지 않습니다.
- 수직 스크롤은 끕니다. 필요한 행과 높이를 계산하고 그리드 전체가 영역 안에 들어가는지 검증합니다.
- 고정 버튼 크기·K개·제한된 높이를 항상 동시에 만족할 수는 없습니다. 부족하면 Inspector에 필요한 최소 높이를 표시하고 구성 오류로 처리합니다. 아이템을 숨긴 채 정상 표시라고 보고하거나 몰래 스크롤로 바꾸지 않습니다.
- 화면이 좁을 때 사용할 K와 크기·열 정책을 개발자가 조절할 수 있게 하고, 유효한 모바일·데스크톱 예제를 제공합니다. 자동 반응형 K는 후속 확장이며 이번에는 고정 K의 의미를 보존합니다.

### 상태 갱신 규칙

- 기본 표시 모드는 VerticalScroll이며 Inspector와 런타임 API에서 전환할 수 있습니다.
- 처음 열기는 All과 첫 위치를 기본값으로 사용합니다. 카테고리 변경은 새 결과의 첫 페이지·첫 행으로 이동합니다.
- 일반 수량 변경은 선택 아이템 ID와 현재 위치를 가능한 한 유지합니다. 마지막 항목 제거로 페이지가 사라지면 마지막 유효 페이지로 보정합니다.
- 표시 모드 변경 시 선택 아이템이 속한 페이지 또는 스크롤 위치를 우선 보존하고 없으면 첫 위치로 돌아갑니다.
- 카테고리·페이지·모드 변경 전에 컨텍스트 메뉴를 닫습니다. 이전 셀 참조로 명령을 실행하지 않습니다.
- 페이지 전환 및 목록 변경의 비동기 아이콘 결과는 ID와 요청 세대를 확인합니다. 늦은 결과가 재사용된 Slot에 표시되지 않게 합니다.

## 7. 컨텍스트 메뉴와 잠정 명령

기존 IActionMenuProvider와 IActionCommandExecutor 경계를 재사용합니다. Slot 선택만으로 사용·버리기를 실행하지 않습니다. 명령 목록과 가시성·실행 가능 여부는 UI 하드코딩이 아닌 정책에서 결정합니다.

아래 값은 변경 가능한 초기 정책이며 게임 규칙의 영구 확정이 아닙니다.

| 명령 | 이번 기본 동작 |
| --- | --- |
| 퀵 슬롯 등록 | 지원 아이템에서 활성화하고 대상 퀵 슬롯을 선택하게 합니다. 점유된 슬롯 교체는 확인하며 취소하면 변경하지 않습니다. |
| 사용 | 현재 구현된 회복 아이템 등 지원 효과만 활성화합니다. 불가능한 이유를 표시합니다. |
| 버리기 | 확장 가능한 명령 ID만 정의하고 기본 숨김 또는 비활성으로 둡니다. 실제 파괴 명령은 이번에 구현하지 않습니다. |

- 등록은 QuickItemLoadout과 기존 QuickItemService 경로를 사용합니다. UI ActionGridPanel에만 아이콘을 직접 추가하지 않습니다.
- 가방에서 선택한 아이템 사용을 위해 퀵 슬롯을 임시로 덮어쓰지 않습니다.
- 필요하면 아이템 ID 기반 사용 핵심을 공통 서비스로 추출하고, 기존 퀵 슬롯 사용은 슬롯에서 ID를 조회한 뒤 같은 핵심을 호출하게 합니다.
- 가방과 퀵 슬롯 사용이 각각 별도 서비스 인스턴스의 잠금만 사용하는 경우를 점검합니다. 세션 단위의 공유 실행 경계에서 중복 실행·수량 검증·효과 적용·차감을 일관되게 처리합니다.
- UI에서 수량을 직접 차감하거나 성공 전 낙관적으로 아이템을 삭제하지 않습니다.
- 명령 실행 직전에 ID, 현재 수량, 대상 캐릭터, 사용 가능 여부를 다시 검증합니다. 오래된 컨텍스트의 상태를 신뢰하지 않습니다.
- 실패와 취소는 성공으로 표시하지 않습니다. 확정된 효과를 화면 닫기 때문에 다시 실행하거나 되돌리지 않습니다.
- 향후 버리기를 활성화할 때 수량 선택·확인·잠금/퀘스트 아이템 제한·퀵 슬롯 연결 처리·저장 정책을 별도 명세하도록 문서화합니다.

## 8. 창 수명, 입력, 자산과 저장

- 기존 inventory 페이지 ID와 GameWindowService를 유지합니다. 창을 열기 전에 세션 준비와 필수 UI 참조를 검증합니다.
- 부모 모달, 컨텍스트 메뉴, 퀵 슬롯 선택 순서의 Cancel 처리를 정의합니다. 취소는 가장 안쪽 UI부터 닫고 초점을 되돌립니다.
- 모달이 열리면 뒤 화면의 포인터뿐 아니라 퀵 아이템 단축키 등 게임 입력도 기존 입력 차단 경계를 통해 제한합니다.
- 키보드·게임패드로 탭, 그리드, 페이지 이동, 컨텍스트 명령과 닫기에 접근할 수 있어야 합니다. 터치에는 우클릭이나 hover를 요구하지 않습니다.
- 탭·페이지 변경 후 탐색 가능한 첫 셀 또는 빈 상태의 탭으로 초점을 정합니다. 모달 종료 시 가방 메뉴 버튼으로 복원합니다.
- InventoryState 변경 이벤트는 명시적으로 구독·해제합니다. 반복 열기에서 구독과 페이지 객체가 누적되지 않아야 합니다.
- 현재 화면에 필요한 아이콘을 로드하며, 페이지 교체·창 종료 시 소유 Lease와 비동기 작업을 정리합니다.
- 로딩·빈 가방·실패 상태를 구분합니다. 세션 실패를 빈 가방이나 Demo 데이터로 조용히 대체하지 않습니다.
- 필터·번호 페이지는 이번에는 저장하지 않습니다. 보유량과 퀵 슬롯은 기존 저장 경로를 사용하고 호환성을 유지합니다.

## 9. 프리팹, 기본 데이터와 생성 도구

- GameMenuPanel, GameMenuScreen, ModalWindowHost의 기존 구성과 외부 서비스 소유권을 유지합니다.
- 가방 본문을 재사용 가능한 하위 프리팹으로 분리하고, 탭·그리드·페이지 컨트롤·상태 UI의 필수 내부 참조를 저장합니다.
- 새 코드만 추가하고 기존 저장 프리팹을 그대로 두지 않습니다. 저장 후 다시 로드하여 참조를 검증합니다.
- TMP_MainScene의 기존 메뉴와 창 서비스를 갱신하되 위치·부모·형제 순서·사용자 Override를 보존합니다. Scene 전체 재생성을 실행하지 않습니다.
- 새 Builder는 AGENTS.md의 Prefab 일괄 Rebuild 등록 규칙을 따릅니다. 콘텐츠 초기화와 운영 Prefab 재생성을 분리합니다.
- 테스트 데이터는 별도 Demo 또는 테스트용 세션에 둡니다. 여러 카테고리, 최소 3페이지 분량, 빈 카테고리, 사용할 수 없는 아이템을 포함합니다.
- 실제 저장 데이터나 새 게임 인벤토리에 테스트 아이템을 지급하지 않습니다.

## 10. 구현 순서와 검증

1. 기존 inventory 페이지 및 서비스 호출을 추적하고 변경·마이그레이션 범위를 확정합니다.
2. 카테고리 조회, 안정적 정렬과 페이지 계산을 Unity UI와 독립적으로 구현·테스트합니다.
3. 이미지 메뉴와 가방 View를 연결하고 두 표시 모드를 구현합니다.
4. 기존 컨텍스트 경계를 연결하고 등록·지원되는 사용 기능을 구현합니다.
5. 생성 자산과 기존 Scene 연결을 안전하게 갱신합니다.
6. 아래 검증과 문서 갱신을 수행합니다.

검증 기준은 다음과 같습니다.

- 카테고리별 0, 1, K-1, K, K+1 및 여러 페이지 분량을 검사합니다.
- 마지막 페이지 삭제, 카테고리 변경, 미등록 분류·정의 ID, 모드 변경과 잘못된 K를 검사합니다.
- 필터와 표시 변경이 InventoryState를 변경하지 않는지 검사합니다.
- 가방에서 미등록 아이템을 사용해도 퀵 슬롯이 바뀌지 않는지 검사합니다.
- 가방과 퀵 슬롯의 동시 사용·빠른 연속 입력이 중복 차감·효과를 만들지 않는지 검사합니다.
- 등록 대상 선택, 점유 슬롯 교체 취소, 재고 부족과 사용 불가 사유를 검사합니다.
- 느린 아이콘 로딩 중 탭·페이지 변경과 창 닫기를 반복하고 잘못된 아이콘·누수를 검사합니다.
- 긴 번역, 이미지 누락, 좁은 화면에서 페이지 전체 표시와 탭·그리드 입력을 검사합니다.
- 마우스·터치·키보드·게임패드 및 취소·초점 복원을 검증합니다.
- 실제 저장된 Prefab 무결성과 기존 메뉴·모달·퀵 슬롯·저장 복원을 회귀 검증합니다.
- Play Mode의 이미지 메뉴와 두 가방 표시 모드를 캡처하고 해상도 및 적용 설정을 기록합니다. 실제 실행하지 않은 검증은 구분하여 보고합니다.
