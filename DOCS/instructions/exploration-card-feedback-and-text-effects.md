# 탐험 선택 카드 피드백·텍스트 효과·가독성 개선

## 1. 목표와 확정된 방향

현재 다음 노드 선택 카드에 입력 피드백과 조절 가능한 텍스트 효과를 구현하고 텍스트 색상을 재구성한다. 가독성을 최우선으로 하고 미려함은 그다음으로 고려한다. 장기 유지보수가 필요한 소규모 게임에 맞춰 기존 구성요소를 확장한다. 이 문서는 작업 지침이며 아직 구현된 기능의 설명이 아니다.

사용자가 확정한 사항은 다음과 같다.

- 개발자는 색상, 효과 종류, 속도, 강도와 전환 시간을 설정할 수 있다.
- 플레이어는 효과 켜기/끄기와 움직임 줄이기를 조절할 수 있다. 플레이어용 색상·속도·강도 편집기는 만들지 않는다.
- 짧은 선택 확정 연출 후 노드 선택을 실행한다. 개발자는 시간을 설정할 수 있으며 0이면 대기 없이 진행한다.
- 기본 카드 피드백으로 강조, 약한 확대, 눌림을 제공한다.
- 텍스트 일렁임과 움직이는 그라데이션을 실제 구현하되 기본값은 꺼짐이다.
- 향후 희귀도별 외형을 전달할 수 있도록 확장 경계를 마련한다. 이번에는 희귀도 추첨·보상·게임 규칙을 추가하지 않는다.

## 3. 책임 분리와 설정 모델

| 구성 | 책임 |
| --- | --- |
| 카드 표시 프로필 | 기본 색상, 역할별 텍스트 스타일, 입력 상태별 피드백과 전환 설정을 저장한다. |
| 피드백 제어기 | 포인터·포커스·눌림·선택 확정 상태를 해석하고 표시 목표값을 결정한다. |
| 텍스트 효과 제어기 | TMP 문자열·메시를 기준으로 일렁임과 색상 애니메이션을 적용·복원한다. |
| 기존 카드 View·List | 명시적 바인딩, 재사용 초기화와 표시 참조를 제공한다. |
| 기존 탐험 Controller | 선택 요청 검증, 목록 전체 잠금, 확정 연출 대기와 정확히 한 번의 도메인 선택을 조정한다. |
| 플레이어 표시 설정 | 효과 활성화·움직임 줄이기의 현재값과 저장을 관리하고 설정 UI에 연결한다. |

새 이름은 기존 관례를 조사해 정하고, 불필요한 인터페이스·매니저를 늘리지 않는다. 공유 프로필은 ScriptableObject 등 읽기 전용 원본으로 두고 런타임 상태와 override를 분리한다. 공유 Material·프로필 자산을 런타임에 수정하지 않는다. 기본 프로필이 누락되어도 안전한 색상과 입력 피드백으로 동작한다.

향후 희귀도 시스템은 표시 프로필 또는 표시 키를 명시적으로 전달하는 경계만 사용한다. View가 노드 이름·문구·색상을 분석하여 희귀도를 추측해서는 안 된다. 이번에는 희귀도 enum, 확률, 저장 필드와 임시 게임 규칙을 추가하지 않는다. 기본 프로필 → 지정된 표시 프로필 → 인스턴스 override → 입력 상태 → 플레이어의 효과 제한 순으로 적용 우선순위를 문서화한다. 접근성 제한은 희귀도나 상태 연출보다 우선한다.

## 4. 입력 피드백

- Normal, Highlighted, Pressed, Confirming, Disabled에 대응하는 명확한 상태 모델을 둔다. 포인터 hover와 키보드·컨트롤러 focus는 별도로 추적하고 어느 하나가 남아 있으면 강조를 유지한다.
- 터치에는 hover를 요구하지 않는다. PointerDown·Up·Cancel 및 Submit으로 동일한 눌림·확정 피드백을 제공한다. 포인터가 밖으로 나간 뒤 놓기, 스크롤 드래그, 입력 장치 전환을 정상 처리한다.
- 스크롤 드래그는 카드 선택으로 처리하지 않는다. 기존 Button 클릭 판정과 EventSystem 의미를 유지하고 onClick과 Submit에서 같은 선택을 두 번 실행하지 않는다.
- Layout이 소유한 CardRoot의 위치·크기를 애니메이션하지 않는다. MotionRoot 또는 그 아래 전용 피드백 루트에서 배율을 조절한다. 향후 다른 애니메이션이 같은 Transform 값을 덮어쓰지 않도록 소유 채널을 구분한다.
- 추천 초기값은 강조 배율 1.025, 눌림 배율 0.98, 상태 전환 약 0.10초, 확정 연출 약 0.15초다. 이는 조절 가능한 출발값이며 Viewport 잘림·텍스트 흐림이 발생하면 더 작게 조정한다. 이동·진동·소리 효과는 이번 필수 범위가 아니다.
- 이미지·절차적 도형 모드 모두 실제 보이는 배경·테두리·포커스 요소에 피드백을 적용한다. 기존 Button ColorTint와 새 제어기가 같은 색상을 서로 덮어쓰지 않도록 한쪽에 소유권을 둔다.
- 포커스·선택 가능 여부는 색상만으로 표현하지 않는다. 테두리·정적 표식 등 효과를 꺼도 인식 가능한 상태 표시를 유지한다. 장식 Graphic은 raycastTarget을 끈다.

## 5. 선택 확정과 취소 안전성

정상 흐름은 다음과 같다.

```text
유효한 클릭/Submit
→ Run·ChoiceSet·Node ID 및 현재 단계 검증
→ 목록 전체 입력 잠금 및 확정 요청 고정
→ 선택 카드 확정 연출
→ 수명·취소 여부·동일 ID 재검증
→ 기존 도메인 선택을 정확히 한 번 실행
→ 기존 노드 진행 경로 실행
```

- 연출 시작 전에 잠가 다른 카드 클릭과 연속 Submit을 차단한다. 도메인 상태 변경은 연출 완료 후 기존 단일 선택 경로에서 수행한다.
- 선택 시간은 0 이상으로 정규화한다. 0초에서는 불필요한 한 프레임 대기 없이 진행한다. UI 연출은 unscaled time을 사용하고 Time.timeScale=0에서도 영구 대기하지 않는다.
- 목록 교체·Unbind·Scene 종료·비활성화·새 탐험 시작 시 이전 연출과 완료 콜백을 취소한다. 수명 토큰 또는 세대 번호로 늦은 완료를 차단한다.
- 개별 카드 효과 오류 때문에 게임이 멈추지 않도록, 동일한 유효 요청이 여전히 살아 있다면 진단 후 연출을 생략하고 선택을 진행한다. 요청이 취소되거나 오래된 경우에는 절대로 진행하지 않는다.
- 성공·실패·취소에 따라 잠금을 해제하거나 폐기하되, 이미 다음 화면으로 전환된 뒤 이전 목록을 다시 활성화하지 않는다. await 이후 무조건 잠금 해제하는 방식으로 새 요청을 덮어쓰지 않는다.
- 플레이어가 효과를 끄거나 움직임 줄이기를 사용하면 공간 움직임을 생략한다. 보이지 않는 연출을 기다리지 않도록 확정 대기도 생략하되 선택 검증과 잠금은 유지한다.

## 6. 텍스트 효과와 가독성

### 스타일과 기본 색상

- 제목·설명·상태 문구 각각에 기본 색상과 효과 설정을 제공한다. 텍스트 애니메이션은 세 역할 모두 기본 꺼짐이다.
- 기본 어두운 배경에 대한 출발 색상은 제목 `#F3F6FA`, 설명 `#D3DCE8`, 상태 문구 `#FFF1CF`로 제안한다. 이 수치를 검증 완료값으로 취급하지 말고 실제 배경·합성 알파에서 확인하여 조정한다.
- 본문과 작은 상태 문구는 실제 합성 배경 대비 4.5:1 이상을 프로젝트 검증 목표로 삼는다. 애니메이션 그라데이션을 켠 경우에도 가장 어두운 색과 중간 프레임을 검증한다. 대비 계산 방법과 측정 대상 색상을 기록한다.
- 이미지 위 텍스트에는 안정된 불투명 또는 충분한 알파의 배경을 제공한다. 임의 이미지에 대해 글자색 변경만으로 가독성을 보장하지 않는다. 상태 배지와 비활성 상태에서도 필수 정보가 지나치게 흐려지지 않아야 한다.
- 한국어 폰트 fallback, 긴 제목·설명, 큰 글자 크기와 현재 줄바꿈·말줄임 정책을 유지한다. 희귀도 색상은 추후 테두리·장식에 우선 적용하고 필수 텍스트 대비를 희생하지 않는다.

### 일렁임과 그라데이션 애니메이션

- 일렁임은 진폭·속도·문자 간 위상 차이, 그라데이션은 색상 키·속도·방향을 설정할 수 있게 한다. 두 효과는 독립적으로 끄거나 함께 사용할 수 있다.
- TMP의 표시 문자열 자체를 매 프레임 변경하지 않는다. 검증된 기존 효과 시스템이 있다면 재사용하고, 없다면 TMP 메시의 정점·색상을 조절하는 최소 제어기로 구현한다.
- 원본 정점과 색상을 보관하고 매 프레임 원본에서 계산한다. 이전 프레임 변형을 누적하지 않는다. 텍스트·폰트·크기·줄바꿈·fallback submesh 변경 시 원본 캐시를 안전하게 갱신한다.
- 공백·보이지 않는 문자·여러 Material/submesh·한글·리치 텍스트·스프라이트를 처리한다. 다른 TMP 효과와 같은 정점 또는 색 채널을 소유하는 경우 적용 순서를 명시하며 무분별하게 중복 컴포넌트를 붙이지 않는다.
- 텍스트 교체, 효과 끄기, Disable, 재바인딩 시 정점·색상을 복원한다. 재활용된 카드에 이전 진폭·색·위상이 남지 않아야 한다.
- 움직이는 글자가 주변 문구와 겹치거나 Viewport 밖으로 잘리지 않도록 진폭을 제한한다. 매 프레임 ForceMeshUpdate나 Layout 재구축을 기본 구현으로 사용하지 않는다.

## 7. 플레이어 설정

- 기존 시스템 메뉴의 모달 경로에 카드 효과 활성화와 움직임 줄이기 두 설정만 추가한다. 새로운 별도 메뉴·모달 관리자를 만들지 않는다. 기존 페이지를 바인딩하는 실제 경로를 먼저 확인한다.
- 기본값은 카드 효과 켜짐, 움직임 줄이기 꺼짐이다. 프로필에서 기본 꺼짐인 텍스트 효과가 플레이어의 전체 효과 켜짐만으로 자동 활성화되지 않게 한다.
- 효과 끄기는 선택·포커스·비활성 상태를 알려주는 정적 표식까지 제거하지 않는다. 움직임 줄이기는 확대·눌림 이동·텍스트 일렁임과 움직이는 그라데이션을 생략하고 정적인 색상·표식으로 대체한다.
- 설정은 현재 보이는 카드에 즉시 반영되고 Scene 변경과 앱 재실행 이후에도 유지한다. 기존 설정 저장 체계를 우선 재사용하고, 없다면 두 표시 옵션에 한정된 작은 로컬 설정 저장 경로를 만든다. 캐릭터 저장 데이터나 탐험 저장 형식을 변경하지 않는다.
- 누락·손상된 설정에는 기본값을 사용한다. 구독 해제, UI 초기 바인딩 중 잘못된 저장, 반복 콜백을 검증한다. 설정 UI에는 키보드·컨트롤러·터치 조작과 닫기·포커스 복원이 있어야 한다.

## 8. 적용·호환·성능

- 기존 Prefab 계층, 정렬·Padding·도형 설정, 직사각형 클릭 영역, 텍스트의 도형 마스크 분리를 유지한다. 기본 표시 프로필과 필수 참조를 자산에 저장한다.
- TMP_MainScene의 실제 인스턴스와 공유 Prefab, 정당한 생성기 경로에 일관되게 적용한다. 개발자 override와 무관한 Scene 변경은 보존하고 전체 재생성을 기본 적용 수단으로 사용하지 않는다.
- Inspector에 상태별 설정과 제목·설명·상태별 효과를 명확히 구분한다. Runtime 변경 API와 안전한 Editor Preview를 제공하되 OnValidate에서 자산 재생성이나 계속 실행되는 애니메이션을 시작하지 않는다.
- 기존 Tween 패키지·효과 구현이 있는지 확인하고 재사용 여부를 판단한다. 이 작업만을 위해 패키지를 임의로 도입하지 않는다. 예제 설정을 위해 모든 카드에 고유 Material을 무조건 생성하지 않는다.
- 비활성·숨겨진 카드와 효과가 꺼진 텍스트는 지속 갱신하지 않는다. Material 인스턴스와 구독·비동기 작업의 수명을 명확히 관리한다. 모바일 성능은 Editor에서 잘 보인다는 이유로 보장하지 않는다.
- 희귀도 게임 시스템, 사운드·진동, 플레이어용 외형 편집기, 다른 Panel 전체 리팩터링은 범위 밖이다.

## 9. 검증 기준

1. 이미지·절차적 도형 모드에서 Normal/hover/focus/pressed/confirming/disabled를 확인한다. 빠른 진입·이탈, hover와 focus 동시 상태, 포인터 취소, 모달 전환도 포함한다.
2. 연속 클릭·다른 카드 동시 클릭·Submit 반복에도 선택이 한 번만 실행된다. 0초·일반 시간·timeScale=0, 대기 중 Scene 종료와 카드 재사용을 검사한다.
3. 프로필 누락·효과 오류·취소·오래된 요청에 대한 결과를 테스트한다. 연출 실패는 유효한 진행을 막지 않고 취소된 요청은 실행되지 않아야 한다.
4. 한국어와 fallback submesh, 긴 문구, 리치 텍스트, 동적 텍스트 교체, 두 텍스트 효과 조합, 효과 끄기 후 원본 복원을 검증한다.
5. 플레이어 설정의 즉시 적용·재실행 복원·기본값·손상 복구를 검증한다. 효과 꺼짐 및 움직임 줄이기에서 상태가 여전히 구분되고 불필요한 선택 대기가 없어야 한다.
6. 기본·강조·눌림·비활성·그라데이션 프레임의 텍스트 대비를 기록하고 넓은 화면·좁은 화면·스크롤·확대 글자에서 잘림과 가독성을 확인한다.
7. Edit Mode에는 상태 해석·설정 우선순위·시간 정규화·대비·취소/중복 방지 등 분리 가능한 테스트를 추가한다. Play Mode에는 실제 입력·TMP 메시 복원·모달 설정·Scene 수명 회귀를 검증한다.
8. 기존 탐험 선택 및 전투 완료 후 후보 갱신을 회귀 검증한다. 측정 가능한 환경에서는 표시 중인 카드의 GC·메시 갱신·Material 증가를 확인하고 미측정 대상은 분리 보고한다.
